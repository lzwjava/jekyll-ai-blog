**问题：** 人们如何使用 Claude Opus 5.5 制作动画视频？

**回答：**

简短的回答是：**Opus 5.5 并不直接生成视频——它编写代码来渲染视频。** 以下是实际运行机制的说明。

**技术原理**

模型并不会生成视频文件。在经得起验证的演示中，Claude Opus 5.5 并不生成像素——而是编写一个绘制像素的程序。输出的是一个程序，而非视频文件。

那些走红的视频通过一个流水线实现：模型编写动画代码，无头浏览器将每一帧捕获为截图，然后 FFmpeg 将这些帧编码为 MP4。最便捷的环境是 Claude Code，在该环境中模型可以自主地写文件、执行渲染命令、提取帧进行审查，然后修改代码。

**真实工作流程（非“一次提示”）**

该趋势中最常被引用的案例——Donald Jewkes 的音乐视频“Claude Pop”——正是遵循这一模式：创作者口述了一份时长五分钟的概要，转录后超过 9500 个字符——包括角色圣经、逐场脚本、视觉参考，以及图像和视频生成 API 的预算。随后 Claude Code 自主运行了十二小时。

可安装的 `guizang-product-video-skill` 工作流程分为**六个阶段**：

1. **范围界定**——在开始构建之前确认产品、版本、受众、平台、宽高比和风格。
2. **真实内容**——代理读取代码仓库和发布说明，检查哪些功能实际上已发布。
3. **故事板与文案**——将有展示价值的改动转化为镜头列表，并用普通句子编写字幕。
4. **运动**——一个可拖拽的主时间线驱动组件状态、入场和过渡。
5. **音效**——通过代码合成配乐；在重要提示处将音乐压低。
6. **验证**——在交付前检查构图、字体、图像、Logo 和音频同步。

**也存在混合方法**

有些项目使用视频模型来生成包含真实演员和真实物理效果的分镜头，然后让 Opus 5.5 在这些参考画面上重新绘制整个帧——从而实现视频模型单独无法保证的视觉风格一致性。

**“一次提示”的真正含义**

“一键”的说法是作者自己的用语，而他自己的 FAQ 与之矛盾。当被问及仅提供仓库地址是否能完成一部成品影片时，README 回答“不能”——仍需要下载仓库、补充依赖项并确认演示状态。“一键”实际描述的是作者对自己已完全设置好的工具的熟悉程度，而非该工具的实际输入要求。

**成本结构**

帧渲染并非模型 API 调用。以 24fps 渲染 3760 帧，是在你自己的硬件上通过无头 Chromium 完成——消耗的是时间与电力，而非 token。API 账单涵盖的是规划、文案、组件接线和渲染器源代码。正因为这种拆分，该技术才变得经济可行。
