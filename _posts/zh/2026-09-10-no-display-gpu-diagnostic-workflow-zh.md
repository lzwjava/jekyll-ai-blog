## ✅ 手册针对“点不亮”GPU 涵盖的内容

**使用主板集成显卡（iGPU）测试已损坏的独立显卡**——第 6 节，N 卡步骤 11–21：

1. 将显示器连接到 **主板的视频输出端口**，而非 GPU。
2. 进入 BIOS（例如，ASUS H170 PRO：F7 → Advanced → System Agent → Graphics Configuration → **Primary Display = CPU Graphics**），按 F10 保存。
3. 启动进入测试环境，并选择正确的版本目录，例如 `cd 400.250`。
4. **首先设置测试环境**（对于无显示输出的显卡是强制步骤）：
   ```
   ./mods gputest.js -skip_rm_state_init -notest
   ```
5. **关键诊断点：** 如果看到 **PASS 屏幕**，说明该显卡至少能运行测试程序 → 继续执行：
   ```
   ./mats -n 1 -e 5
   ```
   然后使用 `less report.txt` 检查结果（FBI0A0 = VRAM；`0.0.0` = 正常，非零数字 = 故障显存芯片）。
6. 如果 **未出现 PASS 屏幕** → 手册指出这意味着存在 **硬件故障（供电或 GPU 核心问题）**，软件 **完全无法对其进行测试**。
7. 手册甚至提供了后续命令以区分 **核心故障还是显存故障**：`./mods gputest.js -oqa -test 118 -matsinfo`（故障代码 690 = 显存故障）。

## ⚠️ 此场景下的要求/限制

- **CPU 必须具有集成显卡**，且主板必须支持 **Multi-GPU**（手册推荐 ASUS B85/B150/H170）。
- **RAM 容量 ≥ 待测显卡的 VRAM 容量**（例如，8 GB 显存的显卡需要至少 8 GB 内存）。
- 最好在 **传统模式（Legacy mode）** 下启动（UEFI 仅适用于 NVIDIA 显卡）。
- 如果显卡的核心/供电电路完全损坏（步骤 4 从未显示 PASS），手册明确说明 **该软件无效**——此时需要动手维修（检查供电轨、核心），已超出本文档范围。
- 手册主要针对 **显存故障**——因核心损坏导致点不亮的显卡，此工具集只能 *检测* 到（无 PASS），无法进一步诊断。

**总结：** 是的，手册直接涉及点不亮的显卡——通过基于 iGPU 的测试，它能帮助你判断显卡是否可测试、故障是显存还是核心、以及哪个显存芯片损坏。但如果 GPU 核心或供电级已损坏，它只能告诉你到这一步为止。
