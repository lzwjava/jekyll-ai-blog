问题：为什么 `WechatRealFriends` 的扫码登录会失败，提示“需要 iPad 确认登录”？这个项目是不是不能用了？

回答：

是的，你的观察基本正确：**对于如今大多数普通微信账号来说，这类项目实际上已经失效或不可靠了**。

`WechatRealFriends` 基于自动化微信网页登录。原有的流程是：

```
浏览器/网页 API
      |
      | 生成二维码
      v
用户用手机微信扫描二维码
      |
      v
微信确认登录
      |
      v
网页会话 cookie/token
      |
      v
扫描联系人
```

但微信已经改变了安全模型。现在很多账号会出现：

```
扫描二维码
   |
   v
"需要 iPad 确认登录"
```

因为微信把这视为一次**新的网页/设备登录风险**。

你提到的那个项目 issue 也是这种失效的表现：反馈的问题是“检测登录状态失败，手机已经登录，网页一直显示状态失败”。

原因：

1. **微信网页登录并非稳定的公开 API**

这类项目依赖逆向工程内部协议。微信可以随时更改：

* 扫码登录流程
* 设备指纹校验
* 风控规则
* 会话 token
* protobuf/API 端点

且不另行通知。

2. **账号风险等级不同**

有些账号仍可登录：

```
老账号
+ 受信任设备
+ 相同网络
+ 曾使用过网页登录
```

可能还可以。

较新的账号经常遇到：

```
扫码
 -> 安全验证
 -> iPad 确认
 -> 没有额外设备则无法完成
```

3. **iPad 确认是有意设计的**

微信历史上允许：

* Windows 客户端登录
* 网页登录
* iPad 登录

但 iPad 的信任关系比浏览器自动化更强。

所以微信实际上在说：

> “这次登录看起来像是 iPad 客户端。请从受信任的 iPad 上确认。”

这个项目无法合法绕过这一限制。

---

如果你的目标是**找出谁删除了你的微信**，这些项目现在很难实现。

更可行的方案：

### 方案 1：使用微信客户端自动化（困难）

运行真实 Android 设备：

```
Android 手机
    |
uiautomator / accessibility
    |
微信 App
    |
扫描联系人
```

这更接近商业工具的实现方式。

### 方案 2：导出联系人并对比

如果你能获取：

```
friends_today.json
friends_old.json
```

那么：

```python
old = set(open("old.txt").read().splitlines())
new = set(open("new.txt").read().splitlines())

print(old - new)
```

难点在于导出，而非对比。

### 方案 3：使用微信 PC 客户端

一些自动化项目利用：

```
Windows 微信
      |
内存/API 钩子
      |
联系人
```

但这些都很脆弱，并且可能导致账号被封禁。

---

从工程项目角度来看，这个仓库历史上有趣，但我不建议花太多时间让它跑通。真正的技术挑战不再是扫码，而是**逆向微信的设备信任与风控系统**。
