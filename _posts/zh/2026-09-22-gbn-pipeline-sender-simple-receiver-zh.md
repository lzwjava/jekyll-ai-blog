**问题：** 为什么回退N步协议使用 `send_window > 1` 但 `receive_window = 1`？

**回答：**

因为 **GBN 的目标是在发送端实现流水线传输，同时保持接收端极度简单。**

### 1. 发送窗口 > 1 = 流水线

如果发送端每次只能发送一个未确认的数据包：

```text
发送 0 ──────────────> ACK 0
发送 1 ──────────────> ACK 1
发送 2 ──────────────> ACK 2
```

发送端大部分时间都在等待 RTT（往返时间）。

当 `send_window = 4` 时：

```text
发送 0 ──>
发送 1 ──>
发送 2 ──>
发送 3 ──>

             <── ACK 0
             <── ACK 1
             <── ACK 2
             <── ACK 3
```

现在网络变成了一个**流水线**。

发送端无需等待每个数据包的 ACK 再发送下一个。

---

### 2. 为什么 `receive_window = 1`？

GBN 刻意让接收端**完全按序接收**。

假设：

```text
发送端                  接收端

  0 --------------------> 接收 0
  1 --------------------> 接收 1
  2 --------X
  3 --------------------> ???
```

接收端期望收到 `2`。

但它收到了 `3`。

当：

```text
receive_window = 1
```

接收端的行为是：

```python
if packet.seq == expected:
    deliver(packet)
    expected += 1
else:
    discard(packet)
```

因此：

```text
3 → 丢弃
4 → 丢弃
5 → 丢弃
```

它只记得：

```text
expected = 2
```

并持续发送 ACK：

```text
ACK 1
```

最终：

```text
timeout(2)
```

发送端回退：

```text
2 → 重传
3 → 重传
4 → 重传
```

这就是**回退N步**。

---

### 3. 为什么不让接收窗口大于 1？

你可以这样做。但这会走向**选择重传**。

例如：

```text
发送端                  接收端

0 --------------------> ✓
1 --------------------> ✓
2 --------X
3 --------------------> buffer[3]
4 --------------------> buffer[4]
```

此时接收端需要：

```python
buffer = {}

if pkt.seq == expected:
    deliver(pkt)
    expected += 1

    # 可能还需要交付缓存的数据包
elif pkt.seq > expected:
    buffer[pkt.seq] = pkt
```

而发送端需要知道：

```text
2 丢失了
3 已经收到
4 已经收到
```

所以它应该**只重传 2**，而不是 3 和 4。

这本质上就是选择重传。

---

### 4. 设计的权衡

可以将两种协议想象成这样：

```text
                  接收端复杂度
                        ↑
                        |
              选择重传
                        |
                        |  缓存乱序数据包
                        |
                        |
GBN --------------------+----------------→ 带宽利用率
                        |
                        |
                        |
```

**GBN：**

```text
send_window = N
recv_window = 1

发送端：足够复杂以实现流水线
接收端：极度简单
```

**选择重传：**

```text
send_window = N
recv_window = N

发送端：追踪每个数据包
接收端：缓存乱序数据包
```

---

### 5. 一个微妙之处

`receive_window = 1` **并不**意味着网络一次只能发送一个数据包。

它的含义是：

> **接收端只愿意接受一个序号位置——即它期望的下一个数据包。**

仍然可能有大量数据包在网络上传输：

```text
                    网络

发送端                              接收端
  │                                    │
  │── 0 ──────────────────────────────>│ ✓
  │── 1 ──────────────────────────────>│ ✓
  │── 2 ─────────── X                  │
  │── 3 ──────────────────────────────>│ 丢弃
  │── 4 ──────────────────────────────>│ 丢弃
  │                                    │
  │<────────────── ACK 1 ──────────────│
```

因此：

```text
发送窗口 = "我可以同时有多少个未确认的数据包"

接收窗口 = "我愿意接受多少个序号之后的数据包"
```

对于 GBN：

```text
             发送端                     接收端

             [ 0 1 2 3 ]  ───────────>  [ 0 ]
               ↑                           ↑
          多个数据包在传输              只接受下一个
```

这就是全部精髓：**发送端流水线化，接收端简单化**。
