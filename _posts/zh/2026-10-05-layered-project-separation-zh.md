**问题：** 将项目彼此分离的最佳方式是什么？

**回答：**

在软件中使用层层隔离的方式，从最轻量到最强力。选择每个项目实际需要的层级。

**1. 每个项目一个文件夹和仓库（基线）**
- 每个客户或项目一个 git 仓库，放在自己的文件夹中。
- 切勿跨仓库混合代码。如果需要同时打开同一项目的多个分支，请使用 git worktree。

**2. 每个项目独立的 Agent 上下文**
- 为每个项目启动独立的 Agent 会话，不要跨客户复用同一个长对话。
- 在每个仓库中保留一份简短的笔记文件（例如 `NOTES.md` 或 `CLAUDE.md`），涵盖目标、约定、决策、当前状态以及 Agent 不得触碰的内容。
- Agent 在开始时读取该文件，这样你可以快速恢复任何项目，无需重新解释。

**3. 每个项目独立的环境**
- 使用虚拟环境、版本管理器（如 nvm、pyenv）或容器（Docker、开发容器），使项目之间的依赖不会冲突。
- 在 lockfile 中固定版本，确保项目日后能以相同方式构建。

**4. 每个项目独立的凭据和账户**
- 为每个客户分离 API 密钥、云账户、SSH 密钥和仓库访问权限。切勿将一个客户的密钥用于另一个客户。
- 使用密码管理器，为每个客户设置独立的保险库或文件夹。
- 将权限范围限定在项目所需的最低限度。

**5. 用户配置文件或工作区（中等隔离）**
- 为每个客户分离操作系统用户账户或浏览器配置文件，使登录状态、Cookie 和文件彼此分开。
- 这是在购买硬件之前一个很好的中间步骤。

**6. 虚拟机或云端开发环境（强隔离）**
- 虚拟机或远程工作区（如云端开发环境）可以为客户提供一台完全独立的机器，而无需购买实体设备。
- 当合同要求隔离，或项目处理敏感数据时，这是很好的选择。

**7. 独立硬件（最强隔离，仅在被迫时使用）**
- 仅用于平台或安全要求，正如我们讨论过的：iOS 构建、实体设备测试台，或合同规定。

**也要分离你的注意力**
- 将活跃项目限制在你能够处理的范围内，通常是 2–4 个。
- 分块工作。先将一个项目的审查和决策集中完成，再切换到下一个。
- 维护一个简单的状态看板（列表或看板），显示每个项目的状态、下一步行动以及正在等待客户的事项。
- 在切换离开之前写一条简短的交接记录（"我停在哪里，下一步是什么"），这样返回时会很轻松。

**分离业务层面**
- 为每个客户保留独立的合同、发票和文档文件夹。
- 确保每份合同都明确代码所有权以及客户数据的处理方式。
- 切勿将一个客户的机密材料粘贴到另一个客户的会话中。

**经验法则：** 每个项目从第 1–4 级开始，当敏感度或冲突需要时增加第 5 或 6 级，仅在要求别无选择时才使用第 7 级。
