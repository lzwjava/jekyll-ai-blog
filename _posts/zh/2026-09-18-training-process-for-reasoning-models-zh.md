问题：推理模型是如何训练的？

答案：

现代推理模型（OpenAI o系列、DeepSeek-R1、Qwen推理模型等）通常采用**多阶段流水线**进行训练。关键思想是：模型不仅要学习“预测下一个词元”，还要优化为**搜索可能的解决方案并接收正确性反馈**。

简化的流水线：

```
基础LLM预训练
        |
        v
监督式微调（SFT）
        |
        v
推理轨迹训练
        |
        v
带可验证奖励的强化学习（RLVR）
        |
        v
偏好优化/蒸馏
        |
        v
部署模型
```

---

## 1. 从预训练语言模型开始

示例：

```
互联网文本
     |
     v
Transformer
     |
     v
基础模型
```

训练目标：

给定词元：

```
"The capital of France is"
```

预测：

```
" Paris"
```

损失：

$$
L = -\sum_t \log P(x_t|x_{<t})
$$

在此阶段，模型了解语言、代码、数学模式，但无法可靠地推理。

---

## 2. 监督式微调（SFT）

创建示例：

```
问题：
求解：
x^2 + 5x + 6 = 0

答案：
让我们因式分解：
x^2+5x+6=(x+2)(x+3)

因此：
x=-2,-3
```

数据集：

```
(输入, 推理, 答案)
```

使用常规的下一词元预测进行训练。

模型学习：

```
问题
   |
   v
生成中间步骤
   |
   v
最终答案
```

然而，SFT存在一个问题：

模型模仿推理风格，但不一定能学到更好的推理能力。

模型可以写：

```
第1步...
第2步...
因此...
```

但仍然可能是错误的。

---

# 3. 带可验证奖励的强化学习（RLVR）

这是一个重要的突破。

不是由人类对每个答案进行评分，而是使用自动检查器。

示例：

## 数学

模型：

```
求解：
12345 * 6789

 思考
...
 响应

答案：
83810205
```

奖励：

```
检查器(答案)

正确 -> +1
错误   -> 0
```

---

## 代码

模型生成：

```python
def two_sum(nums,target):
    ...
```

运行：

```
pytest tests/
```

奖励：

```
所有测试通过：
+1

失败：
0
```

---

## Lean定理证明

模型：

```
theorem foo :
  a+b=b+a := by
     ...
```

Lean编译器：

```
接受 -> +1
拒绝 -> 0
```

这创建了一个训练循环：

```
          生成解决方案
                 |
                 v
              执行
                 |
                 v
            奖励分数
                 |
                 v
          更新模型权重
```

# 4. 策略优化

模型被视为策略：

$$
\pi_\theta(y|x)
$$

输入：

```
数学问题 x
```

输出：

```
推理轨迹 y
```

奖励：

$$
R(x,y)
$$

训练尝试最大化：

$$
E[R(x,y)]
$$

典型算法：

* PPO
* GRPO
* RLOO
* DPO变体

GRPO思想示例：

生成多个答案：

```
答案 A -> 奖励 1.0
答案 B -> 奖励 0.2
答案 C -> 奖励 0.0
```

增加A的概率：

$$
\nabla_\theta \log \pi_\theta(y|x)R
$$

降低不良轨迹的概率。

# 5. 推理能力为何涌现

一个令人惊讶的事情发生了：

模型发现了有用的内部策略：

示例：

RL之前：

```
问题：
12345*6789 是多少？

模型：
12345*6789=...
```

RL之后：

```
 思考

拆分乘法：

6789*12000
+
6789*345

...

 响应
```

模型学习：

* 分解
* 验证
* 回溯
* 自我纠正
* 计划

因为这些策略能增加奖励。

# 6. 合成推理数据

大型实验室也会生成数据：

```
强教师模型
        |
        v
生成数百万个问题
        |
        v
自动求解
        |
        v
筛选好的解决方案
        |
        v
训练学生模型
```

示例：

生成：

```
1亿个数学问题
```

筛选：

```
仅正确的解决方案
```

训练：

```
学生模型
```

这就是较小推理模型也能变强的原因。

# 7. 测试时计算

推理模型也使用更多的推理计算。

普通LLM：

```
问题
   |
   v
一个答案
```

推理模型：

```
问题
   |
   +---- 方案 A
   |
   +---- 方案 B
   |
   +---- 方案 C
             |
             v
          评判
             |
             v
          最终答案
```

更多思考词元 = 更多搜索。

# 整个系统

现代推理模型看起来像：

```
                互联网/代码/数学数据
                       |
                       v
                 基础Transformer
                       |
                       v
                    SFT
                       |
                       v
             推理演示
                       |
                       v
                 RLVR环境
                       |
        +--------------+--------------+
        |                             |
   生成轨迹                    执行/检查
        |                             |
        +------------- 奖励 ----------+
                       |
                       v
                优化模型
```

最大的概念转变：

**旧的LLM训练：**

> 预测人类文本。

**推理模型训练：**

> 生成动作，接收反馈，朝解决方案优化。

这就是为什么Lean、代码执行、数学验证器、模拟器和游戏变得越来越重要：它们提供廉价、可扩展的真实奖励。
