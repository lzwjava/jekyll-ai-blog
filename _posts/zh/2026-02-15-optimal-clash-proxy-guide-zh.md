**Question:** 在中国大陆使用 Clash 配合这些 rule provider 分组（如 节点选择、谷歌FCM、OpenAI、漏网之鱼、GitHub、全球直连、微软服务、全球拦截、YouTube、应用净化、Google、国外媒体、苹果服务、电报信息）时，考虑到不接受香港代理，但新加坡、日本、台湾、美国等节点可以接受，应该选择哪个选择器分组作为主要的 proxy selector？

**Answer:**

在中国大陆，当使用这类典型的 Clash 配置（通常来自 Loyalsoldier、blackmatrix7 或类似的流行 rule sets）时，**你通常应该选择/设置为默认代理策略组的主选择器组**是：

**🚀 节点选择** (或包含“节点选择”字样的类似名称)

### 为什么 节点选择 是最佳的主选方案

- 在中国流行的大多数 rule sets 中，该分组被专门设计为面向用户的国外/非中国流量的 **proxy selector**。
- 它通常包含一系列优质节点（通常针对中国低延迟或高带宽进行了筛选）。
- 其他分组更加专业化：
  - **国外媒体** → 海外流媒体/媒体网站 (Netflix, Disney+, HBO 等)
  - **YouTube** → 仅限 YouTube
  - **Google** / **OpenAI** / **电报信息** / **GitHub** → 特定服务，通常指向针对该服务优化的快速节点
  - **🍎 苹果服务** / **Ⓜ️ 微软服务** → Apple / Microsoft 服务（在某些规则中，这些服务在特定地区效果更好，甚至会被设为 DIRECT）
  - **🌍 国外媒体** (有时与国外媒体重叠)
  - **漏网之鱼** → 最终兜底分组，用于处理未匹配到先前规则的国外 IP/域名（非常重要的 fallback）

**选择选择器的推荐优先级（2026 年中国大陆背景下）：**

1. **🚀 节点选择**
   → 最常用且推荐的通用浏览默认/全局选择器，在配置良好的规则中，几乎所有国外流量都会流向这里。

2. **漏网之鱼**
   → 如果你想要更严格/更保守的路由策略（所有未明确匹配的内容都通过代理）。这是一个非常流行的第二选择。

3. **国外媒体** 或 **YouTube**
   → 仅当你的主要用途是流媒体（Netflix, YouTube 等）并且你希望为其分配专用节点时（有时这些节点具有更好的解锁能力）。

### 中国大陆 rule sets 常见行为快照

| 分组名称 | 典型用途 | 推荐作为主选择器？ | 备注 (中国使用情况) |
|---------------------|------------------------------------------|--------------------------------|--------------------------------------|
| 🚀 节点选择 | 通用国外流量选择器 | **是 – 最佳默认项** | 通常包含 SG/JP/US 等 |
| 漏网之鱼 | 兜底国外流量 | 是 (备选默认项) | 安全且全面 |
| 国外媒体 | 流媒体/媒体解锁 | 有时 | 如果有解锁问题，适合 Netflix/Disney |

| 苹果服务 / 微软服务 | 为中国 App Store 提供更好兼容性 | 否 (通常为 DIRECT) | 许多规则将其设为 DIRECT |
| 全球直连 | 国内 / 直连流量 | 否 | 必须保持 DIRECT |
| 全球拦截 | 广告/追踪器拦截 | 否 | 设为 REJECT |

### 针对你代理列表的实用建议

- 你的可用优质节点主要是 **新加坡 (SG)**, **日本 (JP)**, **台湾 (TW)**, **美国 (US)** 等（香港节点较差/不可用）。
- 在 **节点选择** 分组中 → 手动选择或使用 **url-test / fallback / load-balance** 策略，并选择表现最好的 SG/JP/US 节点（忽略香港节点）。
- 如果 **节点选择** 包含过多的香港节点且延迟不佳 → 将主策略切换到 **漏网之鱼**（它通常继承类似的代理，但预过滤较少）。

**2025–2026 年中国大陆大多数用户的设置：**

GLOBAL / FINAL 策略组 → **🚀 节点选择**

这是最安全且最普遍的建议。
