问得好——我有一个强有力的假设。可能的根本原因：**250W 特斯拉 M40 的功耗尖峰触发了这台机器老旧电源的过流保护。**

## 为何发生

M40 从以下状态变化：

- **空闲时**：刚才 `nvidia-smi` 显示 **16W**（仅需这么多电就能保持运行）
- **加载模型时**：当 llama-server 启动，CUDA 初始化并向 GPU 推入约 10GB 数据，显卡功耗突然飙升到 **170–250W**

在一台 2016 年左右的台式机上，电源额定功率很可能只有 400–500W（或已老化），瞬间的 +200W 尖峰可能触发过流保护 → **瞬间断电**。再次按下电源按钮就能重启（这正是你看到的——它“关机”了，而不是“卡死”）。

> 对比：之前那次在**下载模型**时宕机可能情况不同——那是 Killer E2400 网卡在网络负载下卡死（一个已知的 Linux `alx` 驱动问题）。那台机器实际上一直处于*运行*状态（uptime 持续增加）。

## 重新开机后我的计划

我会立即做三件事（全部远程操作，无需关机）：

1. **限制 GPU 功耗**，让这种尖峰不再发生：

   ```bash
   sudo nvidia-smi -pm 1        # 持久模式
   sudo nvidia-smi -pl 150      # 功耗限制到 150W
   ```

   14B 模型在 150W 下仍能正常运行（速度稍慢，安全得多）。

2. **检查日志**，找出真正的元凶：上一次启动的 PSU/MCE/温度错误：

   ```bash
   journalctl -b -1 -p err      # 上一次启动的错误
   sudo dmesg | grep -iE "NVRM|thermal|mce|power"
   ```

3. **检查散热**——M40 是一款被动散热的服务器显卡（无风扇，仅靠散热片）。你机箱内的气流情况如何？M40 的 **8-pin 电源** 是否已连接？另外——电源标签上的**额定功率**是多少？这将确认诊断结果。
