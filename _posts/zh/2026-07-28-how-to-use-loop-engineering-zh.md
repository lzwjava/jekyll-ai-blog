**循环工程**是一种将软件/AI工作流设计为持续反馈循环的实践：

```
观察 → 决策 → 行动 → 验证 → 学习 → 重复
```

它对 **AI 代理**特别有用，因为大语言模型并非确定性编程工具。你无需编写每一步，而是构建一个系统，让代理能够检查现实、采取行动、检测故障并改进。

一个简单的思维模型：

```
             ┌──────────────┐
             │   目标       │
             └──────┬───────┘
                    ↓
             ┌──────────────┐
             │   观察       │
             │ 日志/文件/数据库│
             └──────┬───────┘
                    ↓
             ┌──────────────┐
             │   推理       │
             │ LLM 规划     │
             └──────┬───────┘
                    ↓
             ┌──────────────┐
             │   行动       │
             │ 工具/代码    │
             └──────┬───────┘
                    ↓
             ┌──────────────┐
             │   评估       │
             │ 测试/检查    │
             └──────┬───────┘
                    │
              是否成功？
              /     \
            是      否
            停止    重试
                    ↑
                    └────────
```

## 1. 传统工程 vs 循环工程

传统方式：

```
人类：
  理解问题
  编写设计
  编写代码
  测试
  部署
```

循环工程：

```
人类：
  定义目标

代理：
  检查仓库
  发现缺失部分
  修改代码
  运行测试
  读取错误
  修复
  重复
```

人类成为 **目标设定者 + 系统设计者**。

代理成为 **执行循环**。

## 2. 基础编码代理循环

示例：

目标：

> "让这个旧的 Java 项目运行起来。"

代理循环：

### 步骤 1：观察

```
ls
find .
cat pom.xml
git status
```

代理发现：

```
pom.xml 存在
mysql 依赖缺失
数据库配置缺失
测试失败
```

### 步骤 2：规划

LLM：

```
问题：
- 应用程序无法启动

假设：
- 缺少数据库 schema

行动：
- 创建 docker mysql
- 生成 schema
- 更新配置
```

### 步骤 3：行动

代理：

```bash
docker compose up mysql

mvn test
```

失败：

```
表 user 不存在
```

### 步骤 4：反馈

代理读取错误：

```
CREATE TABLE user ...
```

创建迁移文件：

```
db/migration/V1__init.sql
```

再次运行。

循环继续。

## 3. 重要部分：验证循环

糟糕的代理：

```
询问 LLM
编写代码
完成
```

好的代理：

```
编写代码
↓
编译
↓
测试
↓
检查错误
↓
修复
↓
重复
```

示例：

```python
while True:
    plan = llm(goal, context)

    result = execute(plan)

    feedback = evaluate(result)

    if feedback.success:
        break

    context.append(feedback.error)
```

这是现代编码代理的核心。

## 4. 多代理循环工程

对于更大型的系统：

```
             管理者代理
                  |
     ┌────────────┼────────────┐
     ↓            ↓            ↓

研究代理      编码代理      测试代理

     ↑            ↑            |
     └────────────┴────────────┘
              反馈
```

示例：

软件迁移：

```
管理者：
"将 Spring Boot 2 升级到 3"

研究代理：
- 查找破坏性变更

编码代理：
- 修改依赖

测试代理：
- 运行 CI

审查代理：
- 检查差异
```

## 5. 生产级 AI 员工循环

针对你的"数字员工"想法：

每个代理应具备：

```
代理
 |
 +-- 目标
 |
 +-- 记忆
 |
 +-- 工具
 |
 +-- 事件循环

6. 验证
7. 通知人类
```

通知：

```

已创建表：
orders

验证结果：
127 个测试通过"
```

## 6. 关键工程原则

不要优化提示词。

要优化 **循环**。

弱：

```
"你是一名专家开发者。
修复此问题。"
```

强：

```
目标：
修复应用程序启动。

循环：

1. 检查错误日志
2. 形成假设
3. 做最小改动
4. 运行测试
5. 分析失败
6. 重复直到全部通过
7. 报告变更
```

循环创造可靠性。

## 7. 实用架构

一个可行的技术栈：

```
                 用户

                  |
             任务队列

                  |
             代理运行时

        ┌─────────┼─────────┐

     规划器    执行器    评估器

        |          |          |

      LLM       工具       测试

                  |
              环境

                  |
              反馈
```

技术选型：

* 代理运行时：Python/TypeScript
* 工具：shell、git、浏览器、数据库
* 记忆：SQLite/Postgres/向量数据库
* 评估：pytest、CI、基准测试
* 事件：Redis/Kafka/NATS
