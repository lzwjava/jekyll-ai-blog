问题：**在2026年9月的当下，我们实际上能构建哪些AI产品？**

答案：

最大的转变在于 **AI产品现在能够执行操作，而不仅仅是生成内容**。智能体可以操作浏览器/桌面、终端、文件、API、记忆，以及与其他智能体协作；在专业开发者中，编码智能体的采用率已经非常高。（[OpenAI Developers][1]）

基于你的技术栈——模型训练 + 智能体 + 命令行界面 + 咨询——我建议你思考 **“能够替代工作流程的软件”**，而不是另一个聊天机器人。

### 1. 面向中小企业的AI员工

为一家公司提供一个可以访问以下资源的智能体：

```text
Gmail
Slack
Google Drive
CRM
ERP
浏览器
SQL
内部API
```

然后：

```text
CEO：“处理本周的入站线索。”

智能体：
  → 阅读邮件
  → 筛选线索
  → 调查公司
  → 更新CRM
  → 起草回复
  → 安排通话
  → 跟进
  → 报告异常
```

这在技术上现已可行：当前的智能体运行时支持工具、多步骤执行、状态管理、编排和计算机操作。（[OpenAI Developers][2]）

**商业模式：** 每家公司每月500–5,000美元。

关键不在于模型本身，而在于 **掌握特定的业务工作流程**。

### 2. “Claude Code for X”

这可能是最有趣的类别。

Claude Code证明了智能体可以将：

```text
问题 → 检查仓库 → 编辑 → 运行测试 → 调试 → PR
```

转化为产品。

同样的架构适用于：

```text
“AI会计”
“AI站点可靠性工程师”
“AI数据工程师”
“AI安全工程师”
“AI研究员”
“AI合规工程师”
“AI增长工程师”
```

例如：

```text
AI站点可靠性工程师

警报
  ↓
智能体读取日志
  ↓
检查指标
  ↓
检查最近部署
  ↓
重现问题
  ↓
提出/执行修复
  ↓
运行测试
  ↓
回滚或部署
  ↓
编写事故报告
```

OpenAI当前的智能体菜谱已明确展示了诸如站点可靠性工程师、数据分析师、支持智能体、安全扫描器、数据库变更分析以及迭代修复循环等模式。（[OpenAI Developers][3]）

**这比另一个通用聊天界面更具防御性。**

### 3. CLI中的AI软件公司

这个想法与你正在构建的内容尤其契合。

设想：

```bash
$ zz "交付Stripe订阅支持"

> 检查仓库
> 检查Stripe文档
> 设计数据库模式
> 实现后端
> 实现前端
> 编写测试
> 运行测试

✓ 修改了43个文件
✓ 通过了127项测试

已创建PR #184
```

但更进一步：

```bash
$ zz company

company/
  agents/
    engineer
    researcher
    designer
    qa
    growth
    support
  memory/
  tasks/
  evals/
  artifacts/
```

产品不是“AI编码”。

而是：

> **让一个人拥有一家虚拟软件公司。**

底层基础设施正变得越来越商品化：沙盒执行、工具、多智能体编排、长时间运行的任务以及计算机交互均已可用。（[OpenAI][4]）

### 4. AI研究实验室

赋予智能体：

```text
网络
论文
arXiv
GitHub
浏览器
Python
GPU
实验运行器
数据库
```

然后：

```text
研究问题
       ↓
文献搜索
       ↓
提出假设
       ↓
实验
       ↓
训练/评估
       ↓
分析
       ↓
新假设
       ↓
重复
       ↓
报告
```

这对 **机器学习研究** 尤其有趣，因为输出结果客观上可测试。

例如：

```text
“能否提高长上下文训练效率？”

智能体生成12个假设
        ↓
运行实验
        ↓
保留有前景的3个
        ↓
运行消融实验
        ↓
生成论文+代码
```

这里重要的产品原语不是“AI研究员”。

而是 **实验循环**。

### 5. AI智能体QA/评估公司

每个构建智能体的公司最终都会遇到：

```text
演示中能工作
≠
可靠地工作
```

因此构建：

```text
生产环境追踪
       ↓
挖掘失败案例
       ↓
生成对抗性任务
       ↓
运行1,000条智能体轨迹
       ↓
判断结果
       ↓
回归检测
       ↓
自动改进提示词/工具
```

你可以销售：

```text
智能体评估持续集成

$ agent-eval run

1,842个场景
1,842条轨迹

成功率：       91.7%
工具错误：      3.1%
幻觉：         1.8%
回归变化：     +4.2%

失败项：
  billing/refund/17
  support/escalation/42
  ...
```

这特别吸引人，因为 **智能体是概率性软件**，传统单元测试远远不够。

### 6. AI浏览器工人

计算机操作改变了传统软件集成的经济性。

不再是：

```text
公司没有API
→ 无法集成
```

你可以：

```text
智能体
 ↓
浏览器
 ↓
现有SaaS
```

智能体实际上可以：

```text
打开Salesforce
点击线索
复制信息
打开ERP
创建客户
上传文档
发送邮件
```

当前的计算机操作系统明确支持操作浏览器和桌面界面。（[OpenAI Developers][5]）

这创造了一个有趣的切入点：

> **自动化那些从未被设计为可自动化的软件。**

潜在垂直领域：

- 保险运营
- 物流
- 会计
- 招聘
- 医疗管理
- 房地产
- 政府文书
- 制造业后台

### 7. 个人“幕僚长”

不是：

> “随便问。”

而是：

```text
你
 ↓
持久化智能体
 ↓
电子邮件
日历
文档
浏览器
联系人
采购
旅行
任务
```

每天早上：

```text
早上好。

有3件事需要你注意：

1. 客户X尚未支付发票#392。
2. 你14:00的会议与航班起飞时间冲突。
3. 研究任务已于夜间完成。

我已经：
✓ 起草了付款跟进邮件
✓ 调整了会议时间
✓ 总结了实验结果

批准#1吗？
```

行业正明确朝着能够执行购物、预订和日历管理等任务的持久化个人智能体迈进。（[Axios][6]）

困难问题不在于智能。

而是 **信任 + 权限 + 记忆 + 身份**。

### 8. AI原生ERP

这更具颠覆性。

不再是：

```text
人类
 ↓
ERP界面
 ↓
表单
 ↓
数据库
```

而是：

```text
人类
 ↓
智能体
 ↓
业务状态
```

示例：

```text
“下个月我们应该订购多少库存？”

智能体：
  读取销售数据
  读取季节性数据
  读取供应商信息
  读取现金状况
  运行预测
  模拟场景
  提出订单建议
```

然后：

```text
“执行。”

→ 创建采购订单
→ 与供应商谈判
→ 更新库存
→ 安排发货
```

界面变成次要的。

**意图 → 智能体 → 状态转换** 成为基本原语。

## 我个人会主攻的3个产品

如果我坐在你旁边，我们想要一个 **本月就能交付** 的东西，我会缩小到：

| 产品                                        |       MVP |                              护城河 |
| ------------------------------------------- | --------: | ---------------------------------: |
| **面向一个垂直领域的AI员工**                  | 1–2周     |                     工作流程/数据 |
| **AI软件公司/编码智能体**                    |    1周    |     智能体 + 开发者分发渠道 |
| **智能体评估/QA基础设施**                    | 1–2周     | 评估数据集 + 生产环境追踪 |

我会 **避免**：

```text
❌ 通用聊天机器人
❌ 通用RAG
❌ 通用“AI助手”
❌ 提示词市场
❌ 单一API的AI封装
❌ 另一个图片生成器
```

2026年有趣的单元逐渐变成：

```text
                传统软件
                     │
               ┌─────▼─────┐
               │   界面    │
               └─────┬─────┘
                     │
                   人类
                     │
               ┌─────▼─────┐

                   人类

                     ▼
              ┌──────────────┐
              │   智能体     │
```
