**问题：将前端源代码复制给AI，是理解表单和隐藏规则的有效方法吗？**

**答案：**

是的，这是一种非常有效的技术。现代网页表单本质上是**可执行的规范**。可见的页面只是其中一层，真正的规则通常分布在以下层级中：

```
浏览器 UI
    ↓
HTML 结构
    ↓
JavaScript 验证
    ↓
API 请求载荷
    ↓
后端验证
    ↓
数据库/业务规则
```

前端源代码可以揭示许多页面上不显眼的信息：

### 1. 隐藏字段要求

示例：

```html
<input name="passportNumber" required>
<input name="previousNationality" style="display:none">
```

页面可能不会明确告诉你 `previousNationality` 很重要，但代码会。

AI 可以快速扫描：

* 必填字段
* 正则表达式验证
* 允许的格式
* 下拉选项
* 条件字段

---

### 2. 隐藏在 JavaScript 中的业务逻辑

示例：

```javascript
if (country === "CN") {
    showField("hukou");
}
```

用户看到：

> 国家：中国

但代码说：

> 如果是中国，则要求额外文件。

AI 可以解释这些条件。

---

### 3. API 载荷通常是真正的规范

打开浏览器 DevTools：

```
F12
 → Network
 → 提交表单
 → 检查请求
```

你可能会看到：

```json
{
  "passportNo": "XXXX",
  "educationLevel": "MASTER",
  "employmentHistory": [
     {
       "company": "...",
       "years": 8
     }
  ]
}
```

这告诉你后端实际接收的是什么。

对于移民/政府系统，这尤其有用，因为 PDF 说明可能是为人类编写的，而 API 模式是为机器编写的。

---

### 4. AI 擅长逆向工程表单

一个良好的工作流程：

```
保存页面源代码
        |
        v
将 HTML + JS 提供给 AI
        |
        v
提问：

"分析这个表单。
找出：
1. 必填字段
2. 隐藏验证规则
3. 条件逻辑
4. 可能的拒绝原因
5. 文档要求"
```

然后检查网络调用。

---

你的观察：

> 数字世界 一切皆代码 一切皆规则

对于软件系统来说基本正确。

表单实际上并不是"纸质表单"。它是一个状态机：

```
状态 1：
个人信息

      |
      v

状态 2：
资格检查

      |
      v

状态 3：
文件上传

      |
      v

状态 4：
提交验证
```

用户界面只是这个状态机的可视化。

---

托福考试的经历是一个很好的例子。传统用户看到：

> "考试因网络问题失败。"

一位工程师看到：

```
浏览器
  |
websocket/会话
  |
身份验证
  |
摄像头/麦克风权限
  |
带宽
  |
延迟
  |
服务器超时
  |
监考系统
```

每一层都有日志和故障模式。

拥有技术背景的优势在于你可以调试系统，而不是仅仅忍受它。

下一步的演进可能是：

```
人类：
"填写这份政府申请"

AI 代理：
- 阅读规则
- 分析前端
- 准备文件
- 检查一致性
- 填写字段
- 检测遗漏项
```

许多官僚程序本质上是一个 UI 问题，其底层是确定性规则。AI 非常适合处理这个问题，因为它可以结合非结构化文档、代码和工作流程。
