问题：**停止等待 ARQ（Stop-and-Wait ARQ）** 有哪些优点？

答案：

**停止等待 ARQ** 的基本流程如下：

```text
发送方                         接收方

  数据 #1  ------------------->
           <------------------- ACK #1

  数据 #2  ------------------->
           <------------------- ACK #2
```

如果在超时前未收到 ACK：

```text
  数据 #1  ------------------->
           X  (丢失)

        超时
  数据 #1  ------------------->  重传
           <------------------- ACK #1
```

### 优点

1. **实现非常简单**

   发送方只需跟踪**一个未确认的数据包**：

   ```python
   发送(数据包)
   启动计时器()

   如果收到 ACK：
       发送下一个数据包
   否则如果超时：
       重发当前数据包
   ```

   无需滑动窗口、拥塞/窗口管理或复杂的 ACK 记账。

2. **接收方状态非常小**

   接收方基本上执行以下操作：

   ```text
   接收数据包
       ↓
   验证校验和
       ↓
   如果有效：
       交付数据
       发送 ACK
   否则：
       丢弃数据包
   ```

   使用 **1 位序列号**（`0/1`），还可以检测重复重传。

3. **在不稳定链路上实现可靠传输**

   假设底层信道最终能交付数据包/ACK，停止等待 ARQ 可以从以下情况中恢复：

   * 数据包丢失
   * 数据包损坏
   * ACK 丢失

   关键机制如下：

   ```text
   数据 → ACK
           ↓
        超时
           ↓
        重传
   ```

4. **无接收方缓冲压力**

   由于只有一个数据包在传输中：

   ```text
   发送方 → [一个数据包] → 接收方
   ```

   接收方无需缓冲大量乱序窗口。

5. **正确性易于验证**

   协议状态非常少：

   ```text
   发送方：
       等待数据
       等待 ACK

   接收方：
       等待数据
   ```

   这使其适用于**教学、简单的嵌入式协议、低速链路和非常小的系统**。

### 主要权衡

其致命缺点是**当 RTT 较大时，链路利用率极低**。

假设：

```text
数据包大小 = 1 KB
带宽       = 1 Gbps
RTT        = 100 ms
```

传输 1 KB 仅需：

```text
8192 位 / 1e9 ≈ 8.2 μs
```

但随后发送方需等待约：

```text
100 ms
```

才能收到 ACK。

因此，链路忙约 8 μs，空闲约 100 ms。

大致估算：

```text
利用率 ≈ 传输时间 / RTT
       ≈ 8.2 μs / 100 ms
       ≈ 0.0082%
```

这就是为什么会出现**滑动窗口 ARQ**：保持多个数据包在传输中，而不是每个数据包后都等待。

一个有用的思维模型：

```text
停止等待：

数据 → ACK → 数据 → ACK → 数据 → ACK
       ^^^^^
       大量空闲时间

滑动窗口：

数据 数据 数据 数据 数据 数据
       → → → → →
ACK  ACK  ACK  ACK
```

因此，核心权衡如下：

| 停止等待 ARQ                     | 滑动窗口 ARQ                     |
| -------------------------------- | -------------------------------- |
| 非常简单                         | 更复杂                           |
| 1 个数据包在传输中               | 多个数据包在传输中               |
| 极小缓冲区                       | 较大缓冲区                       |
| 正确性易验证                     | 状态更多                         |
| 高 BDP 链路利用率低              | 高 BDP 链路利用率高              |
| 适用于简单/低速链路              | 适用于高速/长 RTT 链路           |

我还可以从基本原理推导出**停止等待 ARQ 的吞吐量公式** \\(\eta = \frac{T_t}{T_t + 2T_p + T_{ack}}\\)。
