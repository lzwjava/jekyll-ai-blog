问题：**以太网交换机如何使用自学习算法构建网络拓扑图？**

答案：关键区别在于：**普通的二层交换机实际上并不会构建完整的拓扑图。** 其自学习算法构建的是一个 **MAC地址→交换机端口的映射**，通常称为 **MAC/CAM表**。

### 1. 核心算法

假设我们有：

```text
        交换机
      /    |    \
    端口1  端口2  端口3
     PC-A  PC-B  PC-C
```

初始状态：

```text
MAC表 = {}
```

当 `PC-A` 发送一个帧时：

```text
源MAC = AA:AA:AA
目的MAC = BB:BB:BB
```

交换机在 `端口1` 上接收到该帧。

学习规则本质上是：

```python
mac_table[源MAC] = 入端口
```

因此：

```text
AA:AA:AA -> 端口1
```

然后交换机查找目的地址：

```python
if 目的MAC in mac_table:
    转发(目的MAC, mac_table[目的MAC])
else:
    泛洪到除入端口外的所有端口
```

所以经过一些流量后：

```text
MAC表
----------------
AA:AA:AA -> 端口1
BB:BB:BB -> 端口2
CC:CC:CC -> 端口3
```

这就是“自学习”部分。

---

### 2. 为什么这能工作？

因为以太网帧同时包含：

```text
+----------------+----------------+---------+
| 目的MAC        | 源MAC         | 载荷    |
+----------------+----------------+---------+
```

每个帧都给交换机一条信息：

> **“我看到了来自端口Y的MAC X。”**

交换机不需要配置。

从数学角度，可以将其视为学习一个函数：

$$
f: MAC \rightarrow 端口
$$

通过观测：

$$
(MAC_i, 端口_j)
$$

并更新：

$$
f(MAC_i) \leftarrow 端口_j
$$

如果一台机器从一个端口移动到另一个端口，下一个帧会更新映射：

```text
AA:AA:AA -> 端口1

# 机器移动

AA:AA:AA -> 端口4
```

旧条目被替换。

通常还有一个 **老化定时器**，所以不活跃的MAC条目最终会消失。

---

### 3. 但这并不是网络拓扑图

考虑：

```text
       交换机A
       /       \
     PC        交换机B
                /   \
              PC    交换机C
```

交换机A可能会学习到：

```text
AA:AA:AA -> 端口1     # PC
BB:BB:BB -> 端口2     # 交换机B / 其后面的设备
```

但它本身并不知道：

```text
交换机A
   |
交换机B
   |
交换机C
```

因为从A的视角来看，多个下游设备可能只是出现在 **端口2** 后面。

所以MAC学习给你的是：

```text
MAC → 本地入端口
```

而不是：

```text
交换机 → 交换机 → 交换机 → 主机
```

---

### 4. 网络系统实际上如何构建拓扑图？

它们结合了多种协议。

**LLDP** 尤其重要。

交换机定期发送类似以下的内容：

```text
交换机A, 端口3
        ↓
      LLDP
        ↓
交换机B, 端口17
```

交换机B接收到LLDP报文并获知：

```text
邻居:
    本地端口 = 17
    远端设备 = 交换机A
    远端端口 = 3
```

现在控制器可以构建：

```text
交换机A:3 ───── 交换机B:17
```

对每台交换机执行此操作，你就得到一个图：

```text
             ┌─────────────┐
             │   交换机A   │
             └──────┬──────┘
                    │
              A:3 ──┴── B:17
                    │
             ┌──────┴──────┐
             │   交换机B   │
             └───┬─────┬───┘
                 │       │
                PC     交换机C
```

所以概念上：

```text
MAC学习
     ↓
MAC → 端口信息

LLDP
     ↓
端口 → 邻居信息

STP
     ↓
二层拓扑 / 环路预防

ARP / DHCP / 路由信息
     ↓
IP → MAC → 接口关系

     ↓
网络控制器
     ↓
图 / 拓扑图
```

### 5. 有趣的部分：交换机在进行在线学习

这实际上是一个非常简单的 **在线算法**，而不是“AI/ML”。

简化交换机的伪代码：

```python
表 = {}

def 接收(帧, 入端口):
    源MAC = 帧.源
    目的MAC = 帧.目的

    # 自学习
    表[源MAC] = 入端口

    # 转发
    if 目的MAC in 表:
        出端口 = 表[目的MAC]

        if 出端口 != 入端口:
            发送(帧, 出端口)
    else:
        泛洪(帧, 排除端口=入端口)
```

你可以将序列视为：

```text
t0:
{}

t1:
AA -> P1

t2:
AA -> P1
BB -> P2

t3:
AA -> P1
BB -> P2
CC -> P3
```

不需要任何集中式知识。

这是以太网的美妙之处之一：**网络从流量本身发现可达性。**

一个重要提示：如果你所说的“自学习”指的是 **谷歌地图/互联网骨干网监控等系统如何自动推断整个网络拓扑**，那是另一个问题——更接近于 **通过LLDP/CDP、路由协议、traceroute、SNMP、流量数据和概率推断进行分布式图重构**。我也可以从算法角度讲解这个过程，包括如何从原始数据包构建拓扑图。
