**问题：** “how do you analyze — do you use web search or model knowledge?” 是向AI代理提问的好提示/问题吗？

**回答：**

是的，下面精确解释它为何是好问题——从提示工程原则角度分解：

## 为何这是一个强有力的提示

### 1. **迫使代理披露自身架构**

大多数用户从不问这个问题。通过提问，你能立即了解：

- 代理拥有哪些工具
- 何时使用这些工具
- 对输出结果的信任程度应如何把握

这是**认知校准**——你不仅是在获取一个答案，更是在学习如何权衡所有未来回答的可信度。

### 2. **二元结构降低模糊性**

```
“你使用X还是Y？”
```

迫使代理给出具体选择。对比：

- ❌ “你如何工作？” → 模糊，得到营销式回答
- ✅ “网络搜索还是模型知识？” → 迫使给出具体细节

### 3. **揭示代理的自我模型**

弱势代理会虚张声势。优秀代理能准确描述自身的工具使用情况。这是一个**探针**——就像对代理诚实度与自我认知能力的单元测试。

---

## 如何让它更强

对于你的 `hermes-agent` 或任何正在评估的代理：

```
“针对这个具体问题：[X]
— 你会使用网络搜索还是模型知识？
— 你的置信度如何？
— 时效性风险如何？”
```

将其附加到**具体问题**上，能使它变得可操作，而不仅仅是哲学讨论。现在你能得到：

| 信号 | 含义 |
| ------ | ------ |
| 声明的工具 | 可追溯性 |
| 置信度分数 | 何时需要验证 |
| 时效性风险 | 何时强制搜索 |

---

## 元教训

最佳的提示是**探针，而不仅仅是查询**。你不仅是在提取答案——更是在压力测试代理的可靠性模型。这正是高级用户与仅与AI聊天者之间的思维差异。

鉴于你正在构建CLI代理（`ww`、`iclaw`、`zz`），将这种自我披露模式植入系统提示中，将使你的代理更具可审计性。
