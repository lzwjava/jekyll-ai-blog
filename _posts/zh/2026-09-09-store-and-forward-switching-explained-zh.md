问题：在网络交换机中，**存储转发交换 (store-and-forward switching)** 是什么意思？

答案：

**存储转发 (Store-and-forward)** 意味着交换机**先完整接收整个以太网帧，将其存储在缓冲区中，进行检查，然后再转发**到目标端口。

流程如下：

```text
主机 A
  |
  | 以太网帧
  v
+------------------+
|      交换机      |
|                  |
|  1. 接收整个帧   |
|        ↓         |
|  2. 存入缓冲区   |
|        ↓         |
|  3. 检查 FCS     |
|        ↓         |
|  4. 查找 MAC     |
|        ↓         |
|  5. 转发        |
+------------------+
  |
  v
主机 B
```

### 为什么需要“存储”？

假设 A 发送一个 1500 字节的以太网帧：

```text
A
|
|  [以太网帧: 1500 字节]
|  ----------------------------->
|
交换机
```

交换机**不会立即转发前几个字节**。

它会等待直到：

```text
第一个字节
    ↓
...
    ↓
最后一个字节
    ↓
完整帧存入内存
```

然后它在帧的末尾验证 **FCS/CRC**。

如果帧损坏：

```text
FCS 检查 ❌
       ↓
丢弃帧
```

如果有效：

```text
FCS 检查 ✅
       ↓
MAC 表查询
       ↓
从目标端口发出
```

### 与直通转发 (cut-through) 对比

有两种重要的交换方式：

|                                    | 存储转发 (Store-and-forward) | 直通转发 (Cut-through)                    |
| ---------------------------------- | --------------------------- | ---------------------------------------- |
| 是否先完整接收整个帧？             | ✅ 是                        | ❌ 否                                     |
| 转发前进行 CRC/FCS 检查            | ✅                           | 通常 ❌                                   |
| 延迟                               | 较高                        | 较低                                     |
| 是否会传播损坏帧？                 | 否                          | 可能                                     |
| 实现方式                           | 更多缓存                    | 对延迟更敏感                             |
| 当前常见度                         | **非常常见**                | 用于特定低延迟网络                       |

直通转发在读取足够多的以太网头部以获取目标 MAC 后即可开始转发：

```text
帧到达：

[目标MAC][源MAC][类型][负载........]
   ↑
   |
读取此处
   |
   +----> 立即开始转发
```

而存储转发则是：

```text
[目标MAC][源MAC][类型][负载........][FCS]
                                      ↑
                              接收所有内容
                                      ↓
                                 检查 FCS
                                      ↓
                                   转发
```

### 为什么交换机通常使用存储转发

其最大优势在于 **错误隔离**。

设想：

```text
PC A ---- 交换机 ---- PC B
```

A 发送了一个损坏的帧：

```text
A
 |
 | 损坏帧
 v
交换机
 |
 | FCS ❌
 X
```

交换机阻止了坏帧到达 B。

这一点在现代交换机中尤为有用，因为它们拥有较大的数据包缓冲区并以极高速运行。

### 一个细微之处

**存储转发不等同于路由。**

二层以太网交换机可以完全基于 MAC 地址进行存储转发：

```text
以太网帧
      ↓
接收
      ↓
FCS 检查
      ↓
目标 MAC
      ↓
MAC 地址表
      ↓
输出端口
```

例如：

```text
MAC 表

AA:AA:AA... → 端口 1
BB:BB:BB... → 端口 2
CC:CC:CC... → 端口 3
```

如果目标地址是 `BB:BB:BB...`，交换机将帧从端口 1 转发到端口 2。

所以，一句话总结：

> **存储转发交换 = 交换机完整接收并缓冲一个帧，对其进行验证（尤其是 FCS），然后通过相应端口转发该帧。**

这也是为什么**存储转发会引入与帧大小成正比的小幅转发延迟，尤其是在输入链路速度下**。
