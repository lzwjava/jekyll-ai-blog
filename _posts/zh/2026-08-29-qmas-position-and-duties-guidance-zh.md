问题：**在QMAS工作经历部分，应如何填写“职位名称”和“职责性质”？**

答案：

QMAS申请须知对此有明确说明：**“职位名称”应填写你确切的官方职称**，需与工作记录/证明文件一致。“职责性质”应**简要描述你工作的核心内容**，例如“计算机软件开发”。（[香港入境事务处][1]）

就你的情况而言，**不建议写冗长的职位描述**。目标是让专业经验的本质一目了然，尤其是当你依靠它来满足**创新及科技**工作经历要求时。

### 示例：后端工程师

**职位名称**

```text
Backend Engineer
```

**职责性质**

```text
Backend software development, system design and development, API development, database engineering, and cloud-based software systems.
```

### 如果实际职称是“软件工程师”

使用：

**职位名称**

```text
Software Engineer
```

**职责性质**

```text
Software development, backend system design, API development, database engineering, and software system maintenance.
```

### 针对AI/ML岗位

如果你的官方职称确实是AI工程师：

**职位名称**

```text
AI Engineer
```

**职责性质**

```text
Artificial intelligence and machine learning development, LLM application development, model training and fine-tuning, and AI system engineering.
```

### QMAS注意事项

不要试图让职称听起来比你的文件更显赫。如果雇佣证明上写的是**“Backend Engineer”**，就如实填写**“Backend Engineer”**，而不要改成“AI Engineer”。

但**“职责性质”可以说明你实际做的工作**。这一点很重要，因为QMAS规定工作经历是否属于特定领域/行业，主要取决于**你的角色、职位或职称的性质**，而不仅仅是雇主的行业。（[香港入境事务处][1]）

因此，我建议按以下结构填写各项：

| 字段                | 填写内容                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| **职位名称** | 雇佣证明上的确切职称                                                                     |
| **职责性质** | 用1句简洁的话描述实际专业职责                                                  |
| **避免**            | 所有岗位都笼统地写“软件工程师”                                                                |
| **推荐**             | 在确实适用时明确提及后端开发 / AI / ML / 云端 / 分布式系统 |

**针对你的QMAS申请**，我会优化每项工作的措辞，清晰体现**研究生/专家级别的技术工作**，同时不夸大任何内容。

如果你能提供**过去5-10个职位名称 + 公司 + 日期**，我可以为每个条目写出确切的QMAS**职位名称 + 职责性质**。
