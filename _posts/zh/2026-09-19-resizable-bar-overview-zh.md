## BAR = 基址寄存器

每个PCIe设备（GPU、网卡、NVMe等）最多有六个 **BAR**（BAR0–BAR5）。每个BAR都是一个请求，向固件/操作系统声明：*“我有一块内存，你需要将其映射到CPU的物理地址空间，这是它的大小。”*

对于GPU来说，最重要的是 **BAR1** —— CPU访问显卡**显存（帧缓冲）**的窗口。

### 旧模型：固定小窗口

历史上，GPU的显存BAR被限制为较小的大小——通常是 **256 MB**——而且是**固定**的；BIOS和操作系统都无法更改它。显存本身要大得多（8、16、24 GB）。因此，CPU一次只能“看到”显存的一个256 MB切片：

```
CPU地址空间
 ┌───────────────┐
 │   ...         │
 │ ┌───────────┐ │      GPU显存（16 GB）
 │ │ BAR1      │ │      ┌──────────────────────────┐
 │ │ 256 MB    │─┼─────►│ 一次只能访问一个          │
 │ │ （窗口）   │ │      │ 256 MB切片                │
 │ └───────────┘ │      └──────────────────────────┘
 └───────────────┘
```

要移动数据，驱动程序必须通过这个256 MB窗口进行缓冲反弹：复制进窗口，通知GPU读取，复制下一块，等等。额外的复制、额外的驱动工作、更低的吞吐量。

**类比：** 显存是一个巨大的仓库。BAR1是装卸码头的大门。没有ReBAR，门就是一个投信口——你仍然可以把所有东西搬进搬出，但每次只能搬一点。

### 可调整大小的BAR（Resizable BAR，ReBAR）

**Resizable BAR** 是一个PCIe规范特性（设备通告的一种能力），允许固件/操作系统在启动时**更改BAR的大小**——通常从小值增加到**完整显存大小**。现在CPU可以直接寻址整个帧缓冲：

```
 ┌───────────────────────────────┐
 │ BAR1 = 16 GB                  │─────► 整个16 GB显存
 │ （整个帧缓冲已映射）           │       直接可寻址
 └───────────────────────────────┘
```

**类比：** 装卸码头的大门被拓宽到与仓库一样大，CPU无需穿梭就能拿到任何箱子。

**带来的好处：** 驱动程序可以直接写入它想要的显存区域（例如，将纹理直接上传到其最终位置），而无需通过小窗口进行分阶段处理。实际游戏中的提升通常是适中的——个位数百分比，在特定工作负载中有时更多。AMD将其营销为 **Smart Access Memory（SAM）**；NVIDIA称为 **Resizable BAR**。本质上是一回事。

### 需要三层协同工作

| 层次 | 要求 |
| --- | --- |
| **GPU** | 必须通告Resizable BAR能力（NVIDIA侧Pascal及以上） |
| **平台/固件** | BIOS/UEFI + 根复合体 + 芯片组必须支持调整大小并分配地址空间 |
| **操作系统/驱动** | 驱动程序必须实际请求更大的大小 |

缺少任何一环，你只能得到旧的固定小BAR。

### 相关但不同的部分：*Above 4G Decoding*

这是一个**前提条件，不是一回事**。大BAR（例如16 GB）无法容纳在4 GB地址边界以下的低MMIO区域中，该区域已被RAM和其他设备窗口占满。**Above 4G Decoding** 告诉BIOS：*“将PCIe MMIO地址范围放置在4 GB线之上是可以的，使用CPU的64位物理地址空间。”* 没有它，大BAR无处可去。

这正是你的P100的情况：

```
P100 BAR1 = 0x4_0000_0000 = 16 GB，64位可预取
BIOS：“无法分配；没有空间”   ← 没有Above 4G窗口存在
```

因此，对于P100，**Above 4G Decoding是你需要的功能**——它允许这个16 GB的BAR1被放置。Resizable BAR是一个*不同*的机制，用于动态调整BAR的大小；Tesla P100暴露的是一个大的**固定**16 GB BAR，而不是可调整大小的，而且无论如何，你的B85平台两者都不支持。

### 一句话总结

> **BAR是CPU用来与设备内存通信的地址窗口。Resizable BAR允许该窗口增长以覆盖整个GPU内存，而不是固定的一个小切片，这样CPU/GPU可以用更少的复制次数交换数据。它需要GPU + 主板 + 驱动的支持——而且大BAR还需要“Above 4G Decoding”才有地方放置。**
