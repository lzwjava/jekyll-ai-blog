## 3. Tree of Thoughts 项目：完整代码讲解

会议的技术核心是高中生分享他自己的**Tree of Thoughts**物理问题求解系统。他在本地运行了它，并逐步讲解了架构。

### 3.1 模型分工：四个角色

该系统是四种模型的协作：

| 角色 | 规模 | 职责 |
|------|------|------|
| **规划模型（Orchestrator）** | 大（120B） | 将问题分解为元任务→任务，逐步规划 |
| **建模模型** | 中等（9B） | 严格遵循规划器的指令，**从未看到完整问题** |
| **评审模型** | 小（0.5B / 4B） | 检查每一步的逻辑，决定噪音/退回/通过 |
| **评估模型** | 小 | 主观评分，例如最终公式是否足够简洁 |

高中生解释了一个关键设计决策：**为什么建模模型不能看到完整问题？**

> 如果让它看到原始问题加上分解后的子任务，它就会忍不住——它会试图“一次性解决整个问题”，而不是遵循分解。所以你必须只给它当前步骤的指令。

资深程序员的评论：“完全正确——你必须给它精确的东西，去掉所有它不需要的东西，否则它会误解你。”

### 3.2 为什么使用 FSM（有限状态机）而不是简单的数据结构

评审部分使用了基于 FSM 的状态管理方法。高中生的理由：

- 一个节点不仅存储“算出了什么数字”——它还存储**边界条件、参数、调用的技能以及这个建模步骤的约束**；
- 在求解物理问题时，每个中间答案都有适用范围，FSM 就是存储这些适用范围和答案的载体；
- 这也是他后来放弃 DAG（有向无环图）合并想法的原因——不同分支几乎永远不会共享相同的前提假设（例如，一个分支假设理想流体，另一个分支添加了一堆修正项）；即使两者都计算出相同的数字，也无法合并。

### 3.3 关于“发散”与“收敛”

他鼓励模型**在最早的节点尽可能发散**，例如生成5-7种不同的方法；之后，如果一个分支只是添加一个修正项（例如阻力），那就没有必要再发散——评审模型自行决定。

一个人文问题可能呈现相反的形状：在反驳现有论点时，实际上可能需要在后期更多地发散。**因此“思维树”的形状本身就是学科特性的反映。**

### 3.4 技能系统与外部 SQL

他将所有“领域知识”外部化：

- 流体力学公式、功能定理等——**模型不允许记忆它们**，它们被写入技能中；
- 模型只调用，不允许自行计算；
- 这避免了模型在没有基于规则约束的地方“胡乱猜测”。

### 3.5 规划器的局限性以及为什么从小模型开始

演示给出的最终答案并不特别准确（例如，一个问题的结果类似于 `v_eff × h`，这种形式不够精确）。他坦诚地说：

> “开源小模型还是太弱了。如果我调用 API，结果肯定更好。”

但他强调了一种工作方法，资深程序员强烈赞同：

> **首先在本地小模型上跑通整个框架，而不是直接跳到 API。**
>
> 小模型会暴露你在调用 API 时永远看不到的小坑；一旦整个流程跑通，换用更大的模型只会让它更好，不会更差。

## 5. Mini-LLM 项目：一个 nanoGPT 风格的训练实现

接下来他们看了第二个项目——一个模仿 nanoGPT 的 mini-LM 训练实现。

### 5.1 多个版本与硬件适配

仓库里有几个版本的原因：他在不同的硬件上运行了相同的代码：

- MacBook（Flash Attention 不可用）；
- 他自己的 3090；
- 同学的 5090；
- 云端的 A100 和 A800。

不同的硬件需要不同的精度、批量大小和并行策略；他保留的版本是 A100 版本。

### 5.2 现场抽查的几个细节

资深程序员以测验的方式快速过了一遍 Transformer 细节：

- **RoPE（旋转位置编码）**：将位置转换为可旋转的向量，使得每个 token 能更好地与其他 token 交互；在自回归情况下，使用正弦/余弦进行位置编码，注册为不参与参数更新的 buffer，并且一起保存；
- **KQV**：K 是这个 token“正在寻找”的东西；Q 是 token 自身的信息；V 是这个 token 可以贡献给 token 之间关系的东西；
- **Flash Attention / mask**：他没有手动编写 mask，因为 PyTorch 内部已经处理了很多；
- **Transformer Block**：每侧一个 LayerNorm + 残差连接，中间是自注意力和前馈网络；
- **训练循环**：Adam 优化器、loss 反向传播、梯度更新、zero_grad——这三行代码在一起。资深程序员的观点：即使你通常不自己写优化器，理解这三行代码的语义对于调超参数或调试也是至关重要的。

### 5.3 数据规模与硬件升级

- 高中生的训练数据大约十几 GB；资深程序员用过 60GB；
- 他从 token 数量反推参数上限，刚过半就停止；
- 他刚刚下单购买了 **NVIDIA Pro 6000** 来替换 3090（理由：3090 对于训练来说太受限，Blackwell 优化还不好，但显存大小是硬性需求）；他父亲在帮忙装机；
- 他的下一个目标：一个**原生多模态模型**。
