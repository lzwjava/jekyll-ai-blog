我来更简单地解释一下，通过一个具体的例子。

## 整体概况

你训练了一个模型。**它有多聪明？** 这份文件通过给它进行标准化测试（就像考试题目）并评分来回答这个问题。最终得分称为 **CORE 分数**。

`scripts/base_eval.py` 负责运行测试；这个文件包含了实际的答题逻辑。

## 3 种题型

**类型 1：选择题**（`multiple_choice`）
> 问：法国的首都是 ___
> - A) 伦敦  - B) 巴黎  - C) 柏林

模型通过计算每个选项的"惊讶程度"（损失值）来评分。最不惊讶的选项就是它的猜测。如果它猜"巴黎"且这是正确答案 → 正确。

**类型 2：填空选择**（`schema`）—— 基本上是选择题的逆向形式
> 补全："这___很好吃"
> - A) "汽车"  - B) "饭菜"

同样的思路：给每个选项评分，选择损失最低的那个。

**类型 3：语言建模**（`language_modeling`）
> 上下文："法国的首都是" → 续写：" 巴黎"

模型必须**逐词**正确预测" 巴黎"的每一个 token。全部正确 → 正确，任何错误 → 错误。（这是最严格的题型。）

## 一道题如何评分（流程）

```
evaluate_task()            ← 评整个考试，若分布式则跨 GPU 分配任务
  └─ evaluate_example()    ← 评一道题
       1. 先给模型展示几个示例问答（少样本）
       2. render_prompts_*()   → 将题目转为文本提示
       3. batch_sequences_*()  → 分词，标注答案部分的起止位置
       4. forward_model()      → 运行模型，获取每个 token 的损失与预测
       5. 与标准答案对比 → 正确或错误
```

第 3 步的技巧：提示共享一个长的共同前缀（题目）。我们只对**答案部分**评分（通过 `find_common_length` 找到），这样模型不会因为共享的设置文本而受到惩罚。

## 最终分数

`base_eval.py` 在约 10 个不同任务上运行此流程，得到每个任务的准确率，然后取平均值 → **CORE 分数**（0–100，越高越好）。
