### 这个适配器真的有用吗？有——我独立验证过了

新生成同分布提示词，贪婪解码，n=64：

```
BASE : 53/64 = 82.8%
TUNED: 64/64 = 100.0%    修复=11  错误=0  净增=+11
```

全部 11 处修复都属于 `(a+b)*c` 这种"困难"级别——它确实不再搞错带括号的乘法了。所以这个适配器是真实有效的。

### 但有两个问题

**1. 思维链目标完全失败。** `rewards/reward_format/mean` **在全部 760 步中均为 0.0**，最终生成的 0/64 条内容包含 `thinking... response`。平均生成长度几乎没有变化 (18 个词 → 18 个词)。模型并没有学会在标签内推理，只是直接回答时更准确了。对于温度 1.0 的基座模型来说，+0.2/+0.3 的标签塑造奖励是遥不可及的小概率事件，而 ±1.0 的正确性奖励完全淹没了它。解决办法：对约 200 个格式示例进行 SFT 预热，或者强制开头标签 (在 prompt/前缀中预置 `thinking`)，这样标签是免费的，只需学习结尾标签和内容即可。

**2. 模型在前约 380 步就饱和了；第二个 epoch 基本浪费了。** 奖励方差为零的组群比例 (→ 零优势 → 零梯度)：

```
第 1-76 步: 30%      第 ️381-456 步: 82%
第 77-152 步: 47%   第 457-608 步: ~82%
第 153-228 步: 64%   第 685-760 步: 82%  (grad_norm=0.01)
```

到末尾约 82% 的组群全是 1.0，因此几乎没有学习信号。数据集太简单了 (基座模型已有 83%)，所以天花板几乎立即就被触及了。

此外：**未见数据无增益**——在更难的保留集问题上 (三位数加法、两位数乘法、更复杂的括号)，基座模型 84.4% vs 微调模型 78.1% (n=32，采样结果，虽有波动但显然没有提升)。它过拟合了狭窄的数据分布。
