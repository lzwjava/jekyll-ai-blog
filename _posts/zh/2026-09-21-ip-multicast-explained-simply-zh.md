问题：什么是IP组播？

答案：**IP组播** 是指 **一个发送方向多个接收方同时发送一个IP数据包**，而不需要向每个接收方分别发送一份副本。

思考：

```text
单播：
                    ┌─ 客户端 A
服务器 ─────────────┼─ 客户端 B
                    └─ 客户端 C
       3 个独立的数据包

组播：
                    ┌─ 客户端 A
服务器 ────────> [网络]
                    ├─ 客户端 B
                    └─ 客户端 C
       1 条逻辑流，由路由器复制
```

关键思想在于，目的地是 **一个代表组播组的IP地址**，而不是某台单独的主机。

### IPv4

组播地址范围是：

```text
224.0.0.0 ~ 239.255.255.255
```

例如：

```text
239.1.2.3
```

接收方表示：

```text
“我想接收发往 239.1.2.3 的流量”
```

这通常通过 **IGMP** 来完成：

```text
客户端 ── IGMP 加入 ──> 路由器
                         │
服务器 ── UDP ─────────> 239.1.2.3
                         │
                         ├──> 客户端 A
                         ├──> 客户端 B
                         └──> 客户端 C
```

路由器维护组播转发状态，并且只向那些包含感兴趣接收方的网络转发该数据流。

### 为什么不能直接用广播？

广播：

```text
服务器 ──> 子网内的每一台机器
```

组播：

```text
服务器 ──> 只有加入该组的机器
```

因此，组播适用于以下场景：

* IPTV / 视频直播
* 服务发现
* 行情数据分发
* 路由协议
* 局域网流媒体
* 向多台机器分发相同的数据

### 重要区别

组播 **不是**：

```text
与 N 个客户端建立 TCP 连接
```

它通常是：

```text
UDP 数据包
    ↓
目的地址 = 组播组
    ↓
网络在必要处复制数据包
```

这就是为什么组播在 **1 → N** 分发场景中可以极其高效。

有一个细节需要注意：**互联网整体上通常不提供任意的端到端组播**。组播更多见于受控网络/数据中心内，这些地方的网络基础设施明确支持诸如 **IGMP** 和 **PIM** 之类的协议。

如果你从系统/网络角度来理解，我还可以详细讲解 **一个 UDP 组播数据包从 `sendto()` → 网卡 → 交换机 → IGMP → 路由器 → 接收方** 的完整过程，包括实际的数据包头。
