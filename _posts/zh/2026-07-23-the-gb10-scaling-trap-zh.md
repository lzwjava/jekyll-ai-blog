问题：为什么 GB10 社区的人警告初学者不要购买 DGX Spark，除非他们准备好购买更多设备？

答案：

他们说的是小型 AI 工作站的**规模陷阱**。

NVIDIA DGX Spark（之前称为 Project DIGITS）是一台非常有意思的机器：搭载 GB10 Grace Blackwell 超级芯片、统一内存，具备大约 **1 PFLOPS FP4 AI 性能**，专为本地运行和微调较大模型而设计。

但社区的警告基本是：

> “一旦你进入 GB10 生态系统，一台机器往往感觉像演示机，而不是最终的生产机。”

为什么？

### 1. 模型规模的增长速度超过你的硬件

一台 GB10 机器大约有 **128GB 统一内存**。

这听起来很大，但现代大语言模型消耗内存很快：

示例：

```
Qwen3-32B
FP16:
32B 参数 × 2 字节 ≈ 64GB
+ KV 缓存
+ 运行时开销
+ 优化器状态（训练）
```

推理还行。

但：

```
Qwen3-235B
```

或

```
DeepSeek-V3 规模模型
```

情况就完全不同了。

你会立刻遇到：

```
单台机器
        |
        v
需要更多内存
        |
        v
再买一个节点
        |
        v
集群
```

---

### 2. AI 开发存在“更大模型成瘾症”

初学者会想：

> “我买 GB10，就能跑本地 AI 了。”

几个月后：

```
第 1 周：
“我能在本地跑 70B 模型了！”

第 3 个月：
“我想微调 100B 模型。”

第 6 个月：
“我想做 MoE 实验。”

第 12 个月：
“我需要多节点训练。”
```

硬件就成了瓶颈。

---

### 3. 单台 GB10 的并行能力有限

对于正经的 AI 工作：

```
单 GPU：
    推理
    实验
    学习

多 GPU：
    训练
    服务
    并行任务
    更大模型
```

研究人员更倾向于：

```
8 × H100
```

而不是：

```
1 × H100
```

对很多工作负载来说。

同理：

```
1 × GB10
```

很适合：

* 学习 CUDA
* 本地推理
* 智能体开发
* 小型微调
* 原型验证

但并不能取代集群。

---

### 4. “买更多”这句话其实说的是工作流

有经验的 AI 人员都知道这个模式：

```
好硬件
      |
      v
更多实验
      |
      v
发现局限
      |
      v
买更多硬件
```

第一台机器会催生对第二台机器的需求。

这类似于：

* 摄影师买更好的相机
* 程序员买更快的笔记本电脑
* 玩家升级 GPU

---

### 5. 但针对你的情况，建议有所不同

考虑到你的背景：

* 训练过 GPT-2 760M
* 运行过 nanoGPT 实验
* 拥有 RTX 4070
* 对智能体 + 本地模型 + 微调感兴趣

GB10 实际上对初学者来说比对你更有意义。

你已经理解：

```
模型大小
↓
显存
↓
批次大小
↓
训练速度
↓
分布式扩展
```

初学者买 GB10 的期待是：

> “我有了自己的 ChatGPT。”

工程师买 GB10 的思考是：

> “这是我的本地 AI 实验室节点。”

心态不同。

这个警告的意思是：

**不要指望买 GB10 就是最终的 AI 机器。要知道它是未来可能组建的本地 AI 集群的第一个节点。**

这也就是为什么很多 AI 工程师不买最贵的单 GPU 工作站。他们优化的路径是：

```
小节点 → 多节点 → 云/集群
```

而不是：

```
一个贵盒子 → 永远不动
```
