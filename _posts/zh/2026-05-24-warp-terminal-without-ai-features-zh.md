**问题：** 有些人会禁用 Warp 的 AI/代理功能，只把它当作一个纯终端来用吗？

**回答：**

是的，绝对有。这是一种有记载且常见的使用方式。人们这样做的原因有几种：

---

## 为什么人们禁用 Warp AI

**隐私/企业政策** — Warp 的 AI 会将你的命令上下文发送到他们的服务器。在银行和企业（正是你的情况）中，这通常会被阻止或违反政策。许多工程师纯粹出于合规考虑禁用它。

**它会碍事** — AI 建议会不请自来地弹出。对于打字速度快、明确知道自己想要什么的经验丰富的工程师来说，自动补全覆盖层是噪音，而不是信号。

**他们已经有更好的 AI** — 如果你正在使用 Claude Code 或自定义 CLI 代理（`ww`、`zz`），Warp 内置的 AI 就显得多余且功能较弱。

---

## 如何实际禁用它

```
设置 → AI → 取消勾选“启用 AI 功能”
```

另外值得禁用的：
```
设置 → 功能 → 禁用“Warp Drive”（云命令共享）
设置 → 隐私 → 将遥测设置为最低
```

之后，Warp 的行为就像一个纯终端 — 分块、分屏、标签页、工作流搜索仍然正常工作。AI 层是一种可选的基础设施，并未集成到渲染器中。

---

## Rust/GPU 渲染器才是真正的价值

Warp 是用 Rust 编写的，并带有 GPU 加速渲染器（Mac 上的 Metal）。这就是它比 iTerm2 或 Terminal.app 感觉更流畅的原因 — 而这与 AI 无关。关心渲染性能的人仅仅因为这个原因而保留 Warp。

---

## 社区观点

在 Reddit（`r/commandline`、`r/MacOS`）和 Hacker News 上，大致分为：

- **“我关掉 AI 使用 Warp，它是最好的 iTerm2 替代品”** — 常见
- **“我不会用它，因为它需要登录”** — 实际上更大的抱怨
- **“光是分块 UI 就值得了”** — 频繁出现

**登录要求** 比 AI 更具争议性 — 截至 2024 年，即使本地使用 Warp 也需要账户。有些人因此完全拒绝它。其他人则接受并禁用 AI。

---

## 你的具体情况

鉴于你通过合同在一家全球银行工作：

- 无论如何都应关闭 AI 功能
- Warp 基于分块的用户体验 + 分屏功能仍比 iTerm2 更有价值
- 你实际的 AI 层是 Claude Code 或你自己的 CLI 代理 — Warp 只是显示窗口

把它当作 **一个更好的终端渲染器，拥有良好的用户体验基本元素**，并禁用所有会回传数据的功能。
