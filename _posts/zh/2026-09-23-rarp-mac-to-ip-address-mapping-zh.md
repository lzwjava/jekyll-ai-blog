问题：什么是 RARP 协议？

答案：**RARP（反向地址解析协议）** 是一种古老的网络协议，允许机器通过其 **MAC 地址** 发现其 **IP 地址**。

其核心理念与 ARP 相反：

```text
ARP：
    IP 地址 ──────> MAC 地址

RARP：
    MAC 地址 ─────> IP 地址
```

### 为什么 RARP 存在？

想象一台无盘工作站启动时几乎没有网络配置：

```text
NIC（网卡）：
    MAC = 00:11:22:33:44:55

        |
        | "我的 IP 是什么？"
        v

RARP 服务器：
    00:11:22:33:44:55 -> 192.168.1.42

        |
        v

客户端：
    我的 IP = 192.168.1.42
```

客户端在以太网层发送 **RARP 请求**，其中包含其 MAC 地址。拥有 MAC → IP 映射表的 RARP 服务器会响应分配的 IP。

### 数据包流向

概念上：

```text
客户端                          RARP 服务器
  |                                |
  |  RARP 请求                     |
  |  "MAC = AA:BB:CC:DD:EE:FF"    |
  |------------------------------->|
  |                                |
  |  RARP 回复                     |
  |  "你的 IP = 10.0.0.42"        |
  |<-------------------------------|
```

RARP 直接运行在 **以太网** 之上，而不是使用 IP，因为此时机器尚不知道自己的 IP。

### 为什么 RARP 消失了

RARP 极为有限：

* 仅提供 IP 地址。
* 需要 RARP 服务器位于 **同一以太网广播域**。
* 无法提供子网掩码、网关、DNS、启动服务器等信息。
* 需要手动配置 MAC → IP 映射。

它很大程度上被 **BOOTP** 取代，随后是 **DHCP**。

现代等价协议：

```text
RARP：
    MAC ──────────────> IP

DHCP：
    MAC + DHCP 请求
           │
           ├── IP 地址
           ├── 子网掩码
           ├── 默认网关
           ├── DNS 服务器
           ├── 租约时长
           └── 其他选项
```

一个微妙但有用的区别：

**RARP 并非简单的“ARP 反向”。** ARP 动态地将 IP 映射到 MAC，是正常 IP 网络的一部分；而 RARP 是一种机制，让尚不知道自身 IP 的主机从服务器获取 IP。
