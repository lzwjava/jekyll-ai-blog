问题：关于网页设计和网页开发技术，有哪些不受欢迎或有争议的观点？

回答：

以下是2025年现代网页设计和前端开发社区中一些真正不受欢迎（通常会被踩或引起激烈争论）的观点。这些是许多经验丰富的开发者心照不宣但很少在公开场合说出来的事情：

- **Tailwind CSS 和 utility-first 框架让大多数设计师编写实际 CSS 的能力变得更差**
  大多数“Tailwind 专家”在没有它的情况下无法编写可维护的自定义 CSS，并且对特异性、层叠或架构一无所知。该框架隐藏了复杂性，直到你需要自定义任何非普通的东西时，一切就会崩溃。

- **Figma 扼杀了优秀的界面设计**
  无休止的原型设计、滥用自动布局和对组件的痴迷，已经产出了一代看起来光鲜亮丽但缺乏灵魂的UI。每个人都因为Figma太容易而抄袭相同的Apple/Google风格模式。

- **暗模式大多是表演性的，并且常常损害可读性**
  对许多人来说，纯黑背景配亮白色文字的感知对比度较低。“系统偏好设置”默认是一个敷衍了事的做法——大多数应用应该选择一种模式并对其进行优化，而不是发布两个半生不熟的主题。

- **90% 的网站不需要 JavaScript 框架（React、Vue、Svelte 等）**
  对于营销网站、博客、文档、作品集和大多数 SaaS 仪表板来说，性能、包大小和复杂性惩罚是不合理的。纯 HTML + 微型 JS（甚至 Alpine.js/HTMX）更快且更易于维护。

- **“设计系统”通常是过度工程化的官僚主义生成器**
  庞大的 Storybook 库包含数百个组件，减慢团队速度多于帮助。大多数公司使用命名良好的 CSS 类和宽松的样式指南会更快地发布。

- **Framer Motion / 花哨的滚动动画是无障碍性警报**
  偏爱滥用 `scroll-snap`、视差和 lenis 顺滑滚动功能会使有前庭障碍的用户感到恶心，并且通常只是伪装成“高级感”的视觉噪声。

- **Webflow 和无代码工具会产生糟糕的代码和锁定**
  生成的标记和 CSS 臃肿、语义差，几乎不可能迁移。它们非常适合原型，但对于任何需要持续两年以上的东西来说都很糟糕。

- **移动优先已过时——大多数用户现在使用大屏手机或桌面设备**
  从 320 像素断点开始会导致局促的桌面布局。“内容优先”或“桌面优先”通常能为2025年人们实际使用的设备产生更好的层级结构。

- **“首屏”仍然极其重要，假装不重要是自欺欺人**
  如果你的标题文本在笔记本电脑屏幕上不滚动就无法阅读，那么你已经失去了一半的访问者。布局偏移指标让人们忘记了人类基本的耐心。

- **大多数“现代”字体（Inter、Satoshi 等）被过度使用，近看很丑**
  它们在 Retina 屏上作为 14 像素正文文本看起来很棒，但在 Windows/非 Retina 显示器上会变得模糊或不一致。系统字体（-apple-system、Segoe UI、Roboto）仍然是可读性之王。

- **AI 生成的网站（例如 Dora、Framer AI）总是感觉有点“不对劲”**
  它们能瞬间达到 80% 的完成度，但剩下的 20%（微交互、边缘情况、品牌声音）仍然需要 AI 尚未具备的人类品味。

- **对拟物化的憎恨是一种过度矫正**
  扁平化设计走得太远了。微妙的深度、纹理和现实的隐喻（看起来可以按下的按钮）通常能提高可供性和愉悦感。

这些观点往往会在设计推特/Reddit/Dribbble 圈子中引发强烈反响，这正是为什么尽管许多资深从业者持这些观点，它们仍然不受欢迎的原因。
