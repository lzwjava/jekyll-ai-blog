**问题：** 什么是“元技能”，以及在这个环境中什么是“技能创造者”技能？

**回答：**

## 元技能

**元技能**是关于技能的技能——它不教你*如何做某件事*，而是教你*如何创建/改进/评估做某件事的技能*。

在这个环境的技能系统中，技能是结构化的 `.md` 文件，为 Claude 提供特定任务的指令（例如，如何创建 `.docx`，如何读取 PDF）。元技能则运作在更高一层：它掌控**技能创建与改进过程本身**。

## 技能创造者（`skill-creator`）技能

以下是需要了解的内容：

## 元技能——概念

**元技能**的抽象层级比常规技能高一级。常规技能教会 Claude *如何执行任务*（制作 `.docx`、读取 PDF、设计 UI）。元技能则教会 Claude *如何创建、评估和改进技能本身*。

来自机器学习领域的类比：技能是模型，元技能则是该模型的训练循环加评估框架。

## `skill-creator`——它的实际作用

它是本环境中唯一的元技能。它实现了一个完整的**技能工程循环**：

```
定义意图 → 草拟 SKILL.md → 编写测试用例 → 运行评估 → 审查输出 → 迭代 → 打包
```

具体来说，它涵盖以下内容：

**1. 技能创作**——带有 YAML 前置元数据（`name`、`description`）和 Markdown 指令的结构化 `SKILL.md` 文件。三层渐进式暴露：元数据（始终在上下文中）→ SKILL.md 正文（触发时）→ 打包资源（按需加载）。

**2. 触发优化**——前置元数据中的 `description` 字段是 Claude 决定使用某个技能的主要机制。`skill-creator` 运行一个 `run_loop.py` 优化脚本，对描述进行 A/B 测试，使用 60/40 的训练/测试评估拆分，最多迭代 5 次，以最大化触发率而不导致过拟合。

**3. 评估框架**——编写 `evals.json`，运行测试提示，通过断言检查对输出进行评分，并生成 HTML 审查查看器（`generate_review.py`），在下次迭代前供人工反馈。

**4. 打包**——`package_skill.py` 将最终技能打包成 `.skill` 文件以供安装。

## 技能文件结构

```
my-skill/
├── SKILL.md           ← 必需；包含 YAML 前置元数据 + 指令
└── (可选)
    ├── scripts/       ← 用于确定性步骤的可执行代码
    ├── references/    ← 按需加载到上下文中的文档
    └── assets/        ← 模板、字体、图标
```

## 这对你的重要性

既然你构建 CLI 代理和自动化工具（`ww`、`iclaw`、`zz`），技能系统本质上是**带有版本控制和评估的提示工程**。`skill-creator` 为你提供了一个可复现的循环，用于交付可靠的 Claude 行为——与在微调模型上迭代的理念相同，但位于提示层级。你可以为自己的工作流编写技能（例如，一个用于以你的风格自动生成博客帖子的技能，或一个用于根据你所在银行工程标准进行结构化代码审查的技能），并使用 `skill-creator` 系统地调优和测试它们。
