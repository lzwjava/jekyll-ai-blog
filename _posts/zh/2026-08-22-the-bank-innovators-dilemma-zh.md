问题：为什么像汇丰银行、星展银行和渣打银行这样的传统银行在2010年左右没能打造出类似 Stripe 的产品？

答案：

这是一个典型的**在位者创新者困境**问题。多重力量同时对他们不利：

**1. 组织与文化基因**
银行建立在风险最小化和合规性之上，而非开发者体验。Stripe 的理念——支付应该只需要*两行代码*——在银行的董事会上听起来简直微不足道且不严肃。银行优化的是客户关系经理和企业销售周期，而非自助式 API 文档。

**2. 遗留技术栈**
汇丰银行、星展银行和渣打银行运行着几十年前的核心银行系统（通常是基于 COBOL 的大型机）。在这些基础设施之上构建一个干净、现代化的 REST API 极其困难。而 Stripe 是从一张白纸开始的。

**3. 监管与责任上的保守主义**
银行受到高度监管。让任何开发者在线注册并在几分钟内开始转移资金——无需到访分行、无需合同谈判——这在 2010 年会让他们的合规和法律团队感到恐惧。风险容忍度根本不存在。

**4. 缺乏动力——收入模式的冲突**
银行从*已有的*复杂性中获利颇丰。商户收单、外汇手续费和资金管理服务之所以盈利，正是因为它们不透明且充满摩擦。Stripe 本质上是在把银行通过低效率赚钱的东西商品化。

**5. 他们认为自己的客户是谁**
银行瞄准的是大型企业的首席财务官和财务主管。Stripe 瞄准的是*开发者和初创公司*——那些银行基本忽视的人群。等那些初创公司成长为企业客户时，Stripe 已经拥有了这层关系。

**6. 直接对应创新者困境**
Stripe 早期的利润很薄，客户规模也很小。银行理性地降低了这个市场的优先级。等到初创公司/开发者市场明显变得庞大时，Stripe 已经建立了无法逾越的网络效应、开发者信任和产品护城河。

**为什么星展银行是个例外**
星展银行（新加坡）值得一提——它后来成为亚洲数字化最进步的银行之一，构建了 API 甚至开发者沙箱。但这发生在 *2014–2016 年之后*，当时威胁已经显而易见。即使在那时，由于在其核心市场受到监管限制，他们也无法完全复制 Stripe 那种无摩擦的入驻体验。

**简短回答：**
Stripe 的成功不是因为银行缺乏工程师，而是因为银行的整个*文化、激励机制、监管姿态和客户定义*使得这类产品在内部无法被优先考虑。
