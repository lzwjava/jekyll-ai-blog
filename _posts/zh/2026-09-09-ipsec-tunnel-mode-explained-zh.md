**问题：** 什么是IPsec，隧道模式是如何工作的？

---

**回答：**

## 什么是IPsec？

**IPsec（互联网协议安全）** 是一套协议族，旨在通过验证和加密数据流中的每个IP数据包来保护IP通信。它工作在OSI模型的**网络层（第三层）**，对应用透明。

IPsec提供三种核心安全服务：

- **机密性** — 加密数据，防止在传输过程中被读取
- **完整性** — 确保数据未被篡改（通过HMAC实现）
- **身份验证** — 验证通信双方的身份

---

## IPsec核心协议

| 协议 | 全称 | 用途 |
|---|---|---|
| **AH** | 认证头 | 完整性 + 身份验证（无加密） |
| **ESP** | 封装安全载荷 | 加密 + 完整性 + 身份验证 |
| **IKE** | 互联网密钥交换 | 协商密钥和安全关联 |

在实践中，**ESP** 几乎被普遍使用，因为它同时提供加密和身份验证。

---

## 两种IPsec模式

IPsec运行于两种模式下：

### 1. 传输模式
- 仅对原始IP数据包的**载荷（数据）**进行加密/验证。
- 原始IP头部**保持不变**。
- 通常用于**主机到主机**的通信。

```
[ 原始IP头部 | ESP头部 | 载荷 | ESP尾部 ]
  ← 未加密 →   ←——— 已加密 ———————→
```

### 2. 隧道模式 ← **（你的关注点）**
- **整个原始IP数据包**（头部+载荷）被加密，并封装进一个带有新外部头部的新IP数据包中。
- 内部数据包对网络完全不可见。
- 用于**网关到网关**（站点到站点VPN）或**主机到网关**（远程访问VPN）。

```
[ 新IP头部 | ESP头部 | 原始IP头部 + 载荷 | ESP尾部 ]
  ← 可见 →              ←————————— 已加密 ————————————→
```

---

## 隧道模式 — 工作原理

```
主机A (10.0.1.5)                                            主机B (10.0.2.8)
     |                                                           |
     |── 原始数据包 ──▶ 网关A ──── 互联网 ──── 网关B ──▶|
                              (1.2.3.4)  [加密隧道]  (5.6.7.8)
```

**逐步过程：**

1. 主机A发送一个正常数据包给主机B（源地址：10.0.1.5，目的地址：10.0.2.8）。
2. **网关A** 拦截该数据包，使用ESP加密整个原始数据包，并将其封装在一个新的IP数据包中（源地址：1.2.3.4，目的地址：5.6.7.8）。
3. 封装后的数据包穿越互联网传输 — 中间路由器仅能看到外部头部。
4. **网关B** 接收该数据包，剥离外部头部，解密内部数据包，并将原始数据包转发给主机B。

---

## 隧道模式的主要优势

| 特性 | 优势 |
|---|---|
| **隐藏内部IP地址** | 私有地址对互联网不可见 |
| **保护完整数据包** | 甚至路由信息也被加密 |
| **理想用于VPN** | 站点到站点和远程访问VPN的标准 |
| **可穿越NAT** | 通过NAT穿越技术（NAT-T，UDP端口4500）更易实现 |

---

## IKE — 建立隧道

在任何数据传输之前，**IKE（互联网密钥交换）** 协商一个**安全关联（SA）** — 一组协商一致的算法和密钥：

- **第一阶段（IKE SA）**：在对等体之间建立安全、经过身份验证的通道（使用Diffie-Hellman密钥交换）。
- **第二阶段（子SA / IPsec SA）**：协商用于保护流量的实际ESP/AH参数。

现代部署使用 **IKEv2**，它更快、更可靠，并支持MOBIKE（移动性）。

---

## 快速总结

```
IPsec隧道模式 = 加密(原始IP头部 + 载荷) + 新外部IP头部
```

它是几乎所有现代VPN解决方案（Cisco、Palo Alto、AWS站点到站点VPN、strongSwan等）的基石。
