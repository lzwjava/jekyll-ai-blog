Question: Is it normal for people to use VS Code to develop Java projects?

Answer:

**Yes, it is completely normal** — 并且在 2025–2026 年变得越来越普遍。

许多开发者在 Java development 中使用 **Visual Studio Code** (VS Code)，特别是在以下场景：

- 中小型项目
- Microservices 架构
- Polyglot 代码库（Java + JavaScript/TypeScript + Python + Go 等）
- 快速编辑、脚本编写或 DevOps 相关工作
- 青睐轻量化、快速且高度可定制化编辑器 (Editor) 的团队
- 已经将 VS Code 作为其他语言主要编辑器的开发者
- 偏好免费工具且无授权顾虑的用户

最新的调查清楚地显示了这一趋势：

- 根据 **2025 Java Developer Productivity Report** (JRebel)，**IntelliJ IDEA** 仍以约 84% 的使用率保持第一，但 **VS Code 已经超越了 Eclipse**，成为 **第二大最常用的 Java 工具** (约 31%)。
- 许多 IntelliJ 用户也会同时开启 VS Code 作为辅助编辑器（约 68% 的 IntelliJ 主要用户表示也会使用 VS Code）。
- Microsoft 官方的 **Extension Pack for Java**（加上 Red Hat 的 Language Support for Java）使 VS Code 在处理大多数日常 Java 工作时表现得异常出色：包括良好的 Code completion、Debugging、Maven/Gradle 支持、Spring Boot 辅助工具、Refactoring、Test running 等。

尽管如此，在**大型企业级 Monoliths**（单体应用）、复杂的 Spring Boot 应用程序或需要进行深度 Refactoring 的专业 Java 后端开发者，通常仍更倾向于使用 **IntelliJ IDEA Ultimate**。因为它提供了更深层次的语言智能、更强大的 Refactoring 功能、更好的 Framework 理解（Spring、JPA 等），以及在超大型代码库中通常更快的导航速度。

**Summary — 2026 现状**

- **IntelliJ IDEA** → “经典”专业/企业级 Java 的主流选择
- **VS Code** → 非常正常且受欢迎的选择，尤其受年轻开发者、Full-stack 开发者、Microservices 团队以及不喜欢重型 IDE 的人群青睐
- **同时使用两者** → 极其常见的工作流

所以，是的 —— 在今天使用 VS Code 开发 Java 项目是 **完全正常** 的，绝对不是什么异常情况。
