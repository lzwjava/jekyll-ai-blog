问题：为什么 pi-agent 如此强大？是因为 LLM 已经包含了大部分知识，所以一个带有精确指令的最小化 agent 方法就能胜过大量提示的 agent 吗？

回答：

你的直觉大体正确。核心思想是**将智能从 agent 框架移回基础模型本身**。

现代 LLM 已经具备：

* 数十亿/万亿 token 的预训练知识
* 学习到的编码模式
* 学习到的工具使用模式
* 学习到的推理启发式
* 广泛的世界模型

因此，agent 层不需要再次“教”模型一切。agent 层主要需要提供：

1. **当前任务状态**
2. **可用工具**
3. **约束条件**
4. **良好的执行循环**

像 pi-agent 这样的小型 agent 能够运行良好，是因为前向传播已经非常强大：

```
用户意图
    |
    v
小型系统提示
    |
    v
LLM 潜在知识 + 推理
    |
    v
工具调用
    |
    v
观察结果
    |
    v
下一步行动
```

模型本身填补了空白。

---

本质上权衡如下：

## 最小化 agent

示例：

```
你是一个编码 agent。
必要时使用工具。
解决用户的任务。
```

优点：

* 上下文窗口占用更小
* 推理速度更快
* 成本更低
* 更具创造性
* 约束更少
* 让前沿模型自行决定策略

模型拥有更多的“自由度”。

这更接近于：

```
强模型 + 薄编排
```

---

## 重型 agent（Claude Code 风格）

更重的 agent 通常包含：

```
系统提示
+ 编码规则
+ 安全规则
+ 工作流规则
+ 工具描述
+ 示例
+ 记忆
+ 约定
+ 策略
```

优点：

* 更具可预测性
* 适合数百万用户
* 灾难性错误更少
* 工作流一致

但代价是：

每条规则都会消耗注意力预算。

模型现在需要解决：

```
原始任务
+
遵循 100 条指令
+
避免违反约束
```

有时优化目标会变成：

“遵循框架”

而不是：

“解决用户的问题”。

---

一个有用的类比：

### GPT-4 时代：

模型较弱。

你需要：

```
agent 框架 = 外部大脑
```

因此更多提示、更多链式、更多脚手架。

---

### 2026 年前沿模型时代：

模型更强。

你想要：

```
agent 框架 = 神经系统
模型 = 大脑
```

过多的神经系统控制反而可能降低智能。

---

这与编程语言设计类似。

一个庞大的框架：

```
Spring Boot
+ 200 个注解
+ 约定
+ 生命周期钩子
+ 依赖注入
```

对于企业稳定性来说很好。

但有时一个小型的 Go/Rust 程序会获胜，因为：

```
抽象更少
更接近底层
自由度更高
```

Agent 设计也有同样的谱系。

---

未来有趣的方向可能是：

```
极小的 agent 运行时
+
优秀的模型
+
优秀的工具
+
长期记忆
+
评估循环
```

而不是：

```
巨大的提示
+
数百条规则
+
僵化的流程
```

获胜的 agent 可能更像一个操作系统内核：

```
一万行代码
```

而不是：

```
一百万行 agent 指令
```

---

一个重要提醒：

pi 之所以感觉强大，也是因为你是高级用户。一位有 12 年经验的工程师自然会提供：

```
高质量的任务规格说明
良好的调试反馈
正确的约束条件
```

Agent 不需要弥补糟糕的输入。

对于普通用户，更固执己见的 agent 通常表现更好，因为它们能将模糊的意图转化为可执行的步骤。

所以真正的公式是：

```
专家用户 + 前沿模型 + 薄 agent
        >
重型 agent + 普通用户
```

但：

```
普通用户 + 重型 agent
        >
普通用户 + 最小化 agent
```

有趣的研究问题是：找到最小的“agent 内核”，能在不抑制模型能力的前提下最大化其性能。pi-agent 正在探索曲线上的这个点。
