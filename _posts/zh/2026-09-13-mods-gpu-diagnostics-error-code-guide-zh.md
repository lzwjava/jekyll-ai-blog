以下是MODS如何诊断一张被检测到但出现故障的显卡，以及如何解读其错误代码的方法。

## MODS如何诊断显卡

一旦系统检测到GPU，MODS会运行针对性的硬件测试，对显卡的特定部分进行检测：

| 测试编号 | 测试名称 | 检测内容 |
|---|---|---|
| **3** | **MatsTest** | 内存阵列耦合故障——检测损坏的VRAM芯片、哪条内存通道失效、是读取还是写入失败 |
| **18** | **ByteTest** | 与Mats相同，但基于字节级别——捕获窄内存故障 |
| **19** | **FastMatsTest** | 基于DMA的硬件加速VRAM测试——捕获内存时序/压力问题 |
| **52** | **MarchTest** | “走步1和0”内存模式——捕获DRAM单元保持性问题 |
| **2** | **GLStress** | GPU核心渲染管线——检测像素误比较、着色器/核心问题 |
| **9** | **Random2D** | 2D渲染引擎测试 |
| **127** | **CudaColumnTest** | 长期DRAM数据保持性测试 |
| **17** | **ValidSkuCheck** | 验证熔丝配置、GPC/TPC/FBP/ROP数量——检测禁用/损坏的单元 |
| **50** | **I2CTest** | 检查GPU的I2C总线是否有上拉电阻（常见于死板） |

## 如何解读MODS错误代码

当某项测试失败时，MODS会在`mods.log`中输出类似如下行：

```
Exit 19083: FastMatsTest.Run golden value miscompare [5.293 seconds]
```

自MODS R367起，错误代码为**12位数字**，结构如下：

```
X  YYY  ZZ  NNN  EEE
│   │   │    │    │
│   │   │    │    └── 3位错误代码（1-999）
│   │   │    │
│   │   │    └─────── 3位测试编号
│   │   │
│   │   └──────────── 2位P-state（00、01、05、08等）
│   │
│   └──────────────── 3位PState信息（类型、电源轨、时钟域）
│
└──────────────────── 1位V-F曲线信息
                      （0=静态，1=切换拐点，2=扫描）
```

### 文档中的示例：

```
错误代码：271108119083
```

分解如下：

| 数字 | 字段 | 值 | 含义 |
|---|---|---|---|
| **2** | V-F曲线 | 2 | 扫描V-F曲线 |
| **711** | PState信息 | 7,11,0 | 交叉点，多个交叉参数 |
| **08** | P-State | 08 | P-State 8 |
| **119** | 测试编号 | 119 | CudaRandom测试 |
| **083** | 错误代码 | 83 | 黄金值比较失败（CRC不匹配） |

因此：**CudaRandom测试（#119）在P-State 8下扫描V-F曲线时失败，出现黄金值比较失败（错误代码83）**。

## 使用MODS的实用诊断流程

```bash
# 1. 运行完整制造测试套件
sudo ./mods gputest.js -mfg -l mods.log

# 2. 检查日志中的失败项
grep "Exit " mods.log

# 3. 如果显卡不稳定，重点测试内存
sudo ./mods gputest.js -mfg -test 3    # MatsTest（内存）
sudo ./mods gputest.js -mfg -test 52   # MarchTest（内存）
sudo ./mods gputest.js -mfg -test 19   # FastMatsTest（压力内存）

# 4. 测试渲染管线
sudo ./mods gputest.js -mfg -test 2    # GLStress

# 5. 获取额外内存信息
sudo ./mods gputest.js -mfg -test 3 -matsinfo   # 详细内存通道故障信息
```

### 关键指标：

- **Mats/MarchTest上的错误83（黄金值比较失败）** → **VRAM芯片损坏**（注意哪个比特通道）
- **错误137（EDC内存总线错误）** → **VRAM供电/数据完整性问题**
- **错误649（GPU内存损坏）** → **明确的内存故障**
- **错误144（PCIe错误）** → **PCIe连接或链路问题**
- **错误152（计算测试失败）** → **GPU核心/着色器故障**
- **测试17（ValidSkuCheck）失败** → **熔丝配置错误或单元被禁用**

## TL;DR

对于一张至少能被检测到的“死卡”：

1. `mods gputest.js -mfg` → 运行所有测试
2. 在`mods.log`中查找`Exit XXXX`行
3. 解析**12位错误代码**，确定是哪个测试以及什么错误
4. 内存错误（测试3、19、52） = **VRAM损坏** —— 死卡中最常见的问题
5. 如果所有内存测试都失败 → 可能是**VRAM的供电问题**，而非芯片本身故障
