**问题：** 如果项目需要物理设备（Android/iPhone 应用、Raspberry Pi、Arduino），是否最好使用多台电脑进行开发？

**答案：**

部分正确。物理设备确实是对额外硬件的合理需求，但你通常需要的是“每个目标设备一台机器”，而不是“每个项目一台完整电脑”。

**多台机器确实有帮助的场景**
- **iOS 开发：** 你需要一台 Mac，因为 Xcode 只在 macOS 上运行。如果你的主力机是 Windows 或 Linux，那么 Mac 是刚需，而非奢侈。
- **常开测试台：** 连接了传感器、继电器或其他硬件的 Raspberry Pi 或 Arduino 最好保持通电并持续运行。用它占用你的主力笔记本电脑很快就会变得烦人。
- **设备农场进行测试：** 多台真实手机和开发板可以让你测试不同的 Android 版本、屏幕尺寸和硬件修订版本，这些是模拟器无法完全复现的。
- **长时间运行或有风险的实验：** 一台便宜的备用机器可以运行刷机、压力测试或不稳定的固件，而不会危及你的主力工作站。
- **客户隔离：** 如果客户的硬件、驱动或网络设置可能干扰你的其他工作，专用机器会更干净。

**你很可能不需要更多电脑的场景**
- **Android：** 一台电脑就可以构建，你可以通过 USB 或 Wi-Fi 调试连接多部手机。
- **Arduino 和 Raspberry Pi：** 一台电脑就能编程并和多个开发板通信。Pi 本身也可以作为无头开发目标，通过 SSH 控制，因此不需要在旁边放一台单独的笔记本。
- **不同项目：** 如果它们使用相同的工具链，一台机器配合独立的仓库和环境就足够了。

**一种更经济的思考方式**
1. **一台主力机** 用于大部分编码和代理工作。
2. **如果需要 iOS 开发才配一台 Mac**（Mac mini 通常是最便宜的方案）。
3. **一台小型常开主机或 Pi** 作为硬件测试台，远程控制。
4. **几台真实的测试设备**（手机、开发板）连接到需要它们的机器上。
5. **一个 USB 集线器或网络交换机**，这样设备可以在不增加额外电脑的情况下保持连接。
6. **远程访问**（SSH、远程桌面），这样你可以从主力机访问每台机器，而不是坐在多个键盘前。

**注意事项**
- 每增加一台机器就多一份维护工作：更新、备份、凭证和安全。让机器数量保持在硬件需求允许的最低水平。
- 物理设备的工作自动化起来更慢。代理可以编写甚至刷入代码，但仍需有人验证硬件是否按预期工作。你的注意力仍然是瓶颈，所以不要运行超出你测试能力的硬件项目。
- 尽可能自动化：脚本化刷机、针对连接开发板的自动化测试，以及可以远程读取的日志。

简而言之，当某个平台或设备需要时——比如 iOS 开发需要 Mac，或者需要 Pi/Arduino 测试台——增加额外硬件才有意义。为这个原因添加电脑，而不是把多台电脑作为分离项目的默认方式。
