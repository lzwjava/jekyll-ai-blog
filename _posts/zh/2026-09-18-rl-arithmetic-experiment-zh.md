## 1. 实验设置，具体来说

| 组件 | 值 | 位置 |
|---|---|---|
| 策略模型 | `Qwen/Qwen2.5-1.5B` **基础版**（特意不用 `-Instruct`） | `run.sh` |
| 压缩 | 4-bit NF4 QLoRA + LoRA r=16/α=32（覆盖所有注意力+MLP投影层），梯度检查点 | `train_grpo.py:load_model_and_tokenizer` |
| 数据 | 800 个合成问题（简单 `a+b`，中等 `a*b+c`，困难 `(a+b)*c`），95/5 划分 → 760 训练 / 40 评估 | `make_synthetic` |
| 算法 | TRL `GRPOTrainer`，`loss_type="grpo"`，G=4 次生成/提示，β=0.02 KL 到冻结参考模型，温度 1.0，学习率 5e-6 | `GRPOConfig` |
| 步长结构 | **2 个唯一提示 × 4 次生成 = 每个优化器步 8 个补全** → 2 个 epoch 共 760 步 | 从 `epoch` 字段验证（`2·step/760`） |
| 检查点 | 每 25 步保存一次，`save_total_limit=2` | `grpo_qwen15b_math/` |

奖励是**两个函数的和**（`train_grpo.py:reward_format` / `reward_correctness`）：
- `reward_format` → 输出格式良好的 `思考… 回答` 块且内容≥20 个字符时，最多 **+0.3**
- `reward_correctness` → 答案正确 **+1.0**，错误 **−0.5**，完全没有数字 **−0.7**

## 2. 这里的“RL 训练”是什么意思（与预训练/SFT 对比）

此仓库中的所有其他内容都是**模仿学习**：你有目标文本，然后最小化与之的交叉熵。但这里**完全没有目标推理轨迹**——你只有一个*检查器*。模型自行采样尝试，并通过检查器的尝试会得到强化。这就是全部要点：

```
提示 ──► 策略模型采样 4 个补全（G=4）
              │
              ├─ "… 8 * 1 + 1 = 9"          → 奖励 +1.0
              ├─ "… = 11"                    → 奖励 −0.5
              ├─ " 思考8*1=8；+1=9 回答9" → 奖励 +1.3
              └─ "我无法回答"           → 奖励 −0.7
                    │
        GRPO：优势 = (rᵢ − 均值(r组)) / 标准差(r组)
                    │
        对 LoRA 权重的策略梯度更新 − β·KL(策略‖参考)
```

为什么**专门用 GRPO**：它在 4 个样本的组内对奖励进行归一化以得到优势，因此**不需要价值/评论家网络**——这就是使其能够适配 11.6 GB 显存的内存节省方式。KL 项（β）是一根缰绳，防止策略漂移为利用检查器的胡言乱语。为什么用**基础**模型：指令模型已经有 RLHF 先验与你的奖励对抗，因此你无法将行为变化归因于你的奖励信号。

## 3. 这次运行目前告诉了我们什么

好消息——它作为一个 RL 流水线正在工作：
- **留出集奖励单调上升**：`eval_reward` 0.642 → 0.649 → 0.712 → 0.747 → 0.823 → **0.888**（约第 175 步）。这是泛化，不是记忆。
- KL 保持极小（0.011–0.05），熵 0.5–0.7，`clip_ratio` ≈ 0 → 稳定、温和的更新，没有发散。
- （你看到的负 `eval_loss` 对 GRPO 来说是正常的——它是策略梯度 + KL 目标，不是对数似然。不用惊慌。）

但**实验的科学目标尚未实现**，日志也明确说明了：

**`reward_format/mean` 在 175 步中有 142 步为 0**（最大观测值 0.075，最近一次评估：**0.003**）。模型几乎从不输出 `思考` 标签——它直接回答算术问题。原因是奖励设计的漏洞：
1. `_extract_answer` 回退到“文本中任意位置的最后一个数字”，因此直接回答也能获得全部 **+1.0** 而无需任何推理。
2. 格式奖励只有 +0.2/+0.1——只是 +1.0 的一小部分，而且当答案已经正确时无关紧要。
3. 这些问题对 1.5B 基础模型来说**太简单**了：它接近饱和，因此没有压力去推理。`frac_reward_zero_std ≈ 0.5` 证实了这一点——在一半的组中，所有 4 个样本获得完全相同的奖励，因此优势为 0，**没有梯度流动**。

所以实际学到的是“更可靠地直接回答简单算术”。思维链*没有*涌现。这是关于奖励设计的干净、诚实的负面结果，不是 bug。

## 4. 这项工作的定位和下一步

这个仓库是一个分阶段的 ML 基础设施试验场——数据/分词流水线（FineWeb、codeparrot、climbmix）→ 在 4070/H200 上的预训练运行 → 现在是作为**后训练阶段**的 `grpo-rl`。这次运行是流水线验证的第一级（`--smoke` 2 步模式和 `setup_env.sh` 正是为此存在的）。

自然的下一步，按价值排序：
1. **`--dataset gsm8k`** — 已经接好了（`make_gsm8k`，无需 Makefile，使用你的本地 HF 缓存）。基础模型得分将远低于饱和点，思维链将变得*必要*，`frac_reward_zero_std` 将下降。
2. **堵住捷径**：要求必须有 `思考` 块才能获得正确性奖励（例如，将正确性门控在格式之上，或添加大的格式项）。目前你奖励的是答案，而不是推理。
3. **用新的 `--output-dir` 重新运行**，以便与此近饱和基线进行干净的前后对比。
