问题：OpenClaw（一个AI智能体）在处理大型问题时如何展示实时进度更新——它只是反复发送更新后的状态消息吗？

答案：

## AI智能体如何推送进度更新

是的，本质上如此——但具体实现方式有几种不同机制。以下是其工作原理：

---

### 1. **服务器推送事件（SSE）——最常用**

后端通过持久的HTTP连接将增量更新流式传输到前端。

```
客户端 → POST /run-agent
服务器 → 保持连接打开，推送文本块：
  "data: 检查数据库结构中...\n\n"
  "data: 发现25个表...\n\n"
  "data: 启动编程智能体...\n\n"
```

前端监听并将每个文本块实时追加到用户界面。Claude.ai自身即采用此方式——文本逐字"流式"呈现。

---

### 2. **WebSocket——双向通信**

类似SSE但支持双向通信。智能体在执行过程中发送状态帧：

```json
{ "type": "status", "message": "扫描76个CI3模式中..." }
{ "type": "status", "message": "运行sed替换中..." }
{ "type": "result", "message": "完成。已修复76处匹配项。" }
```

---

### 3. **轮询——更简单但不够优雅**

前端每隔一两秒重复询问"完成了吗？"：

```
客户端 → GET /task/status?id=123  →  { "status": "running", "log": "..." }
客户端 → GET /task/status?id=123  →  { "status": "running", "log": "..." }
客户端 → GET /task/status?id=123  →  { "status": "done",    "result": "..." }
```

---

### 4. **"日志行"如何生成**

智能体本身只需在代码的关键检查点调用日志/发送函数：

```python
emit("检查数据库结构中...")
result = check_db()

emit(f"发现{len(tables)}个表")
run_migration()

emit("启动编程子智能体...")
sub_agent.run()
```

每个`emit()`调用都会通过SSE/WebSocket将消息推送到用户界面。界面将其追加到可见日志中。

---

### 5. **您分享的文档中看到的内容**

您粘贴的转录文本正是这种模式——智能体在执行过程中实时播报自身步骤：

- *"让我检查数据库结构..."* → 执行查询 → 发送结果
- *"发现另一个CI3→CI4问题..."* → 发送发现
- *"这是批量修复任务。让我启动编程智能体..."* → 发送启动事件

这些都是检查点日志消息，通过流式传输逐步输出，让用户知晓智能体仍在运行且取得进展，而非静默挂起。

---

### 总结

| 机制 | 工作原理 | 适用场景 |
|---|---|---|
| SSE | 单向HTTP流 | 简单日志流 |
| WebSocket | 持久双向连接 | 交互式智能体 |
| 轮询 | 重复HTTP请求 | 简单/遗留系统 |

智能体本身只需在每个步骤调用`emit(message)`——传输层（SSE/WebSocket）负责将其实时呈现在您的屏幕上。
