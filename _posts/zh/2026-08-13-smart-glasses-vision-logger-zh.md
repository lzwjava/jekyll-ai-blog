**能否制造一款数字眼镜，持续记录用户所见，并学习其视觉使用习惯——如手机、电脑、户外等场景？**

**答案：能。而且我认为这远不止是“一款视觉应用”，它是一个更有趣的产品。**

核心洞察在于：**你未必需要记录一切，而是需要将用户的视觉体验转化为结构化的时间事件。**

现有研究已指明这一方向。例如，Tobii 的研究型眼镜结合了面向眼睛的内置摄像头和面向场景的外置摄像头；而 MemX 等研究系统则将视觉注意力与场景理解相结合，有选择地捕捉有意义的时刻。（[Frontiers][1]）

消费级硬件也已接近这一目标：Meta 当前的 AI 眼镜已配备摄像头、板载存储、手机集成和拍摄指示灯。（[关于 Facebook][2]）

## 但我还会增加一个传感器：眼动追踪

这是区分：

> **“眼镜上装了摄像头”**

与

> **“一个理解你眼睛正在做什么的设备”**

的关键所在。

你需要的结构是：

```text
             外置摄像头
                  │
                  ▼
            ┌───────────┐
            │ 场景      │
            │ 手机      │
            │ 电脑      │
            │ 道路      │
            └─────┬─────┘
                  │
                  │ 关联
                  │
            ┌─────▼─────┐
            │ 眼动追踪  │
            │           │
            │ 左/右     │
            │ 注视点    │
            │ 眨眼      │
            └───────────┘
```

这样你就能区分：

```text
摄像头看到手机
        ≠
用户正在看手机
```

这一点至关重要。

有人可能坐在手机旁边，但眼睛却在看着另一个人。

眼动追踪能让你回答：

> **用户实际上在看哪里？**

目前已有低功耗的研究方法将眼动追踪集成到眼镜中。2024 年的一项系统展示了基于非侵入式 EOG（眼电图）的追踪技术，功耗极低，据报道连续采集功耗仅为 7.75 毫瓦，可在小型电池上运行数天。（[arXiv][3]）

```text

      ▼

      │

```

对采样帧进行分类：

```python
def classify(frame):
    return vision_model(
        frame,
        """
        对用户的视觉活动进行分类：
        手机、电脑、阅读、驾车、
        步行、户外、人物、电视、未知
        """
    )
```

你不需要 30 FPS（每秒帧数）。

可以这样采样：

```text
每 5 秒 1 帧
```

也就是 **每小时 720 帧**。

但你可能甚至不需要这么多。

使用事件检测：

```text
场景无变化
     ↓
不上传

场景显著变化
     ↓
拍摄

新场景
     ↓
分类
```

这样可以将数据量减少 10 到 100 倍。

例如：

```json

  "start": "09:14",
  "end": "10:47",
  "activity": "电脑使用",
  "confidence": 0.97,
  "estimated_distance_cm": 62

```

然后是：

```json
{
  "start": "10:47",
  "end": "11:03",
  "activity": "户外步行",
  "confidence": 0.94
}
```

这样，你的数据库就变成了**个人视觉历史**，而不是一个庞大的视频档案。

## 一个主要产品约束：隐私

这可能是最困难的部分。

持续录制周围人员活动的摄像头，本质上与智能手表记录心率不同。

Meta 明确在其当前 AI 眼镜上设置了拍摄指示灯，并表示该灯无法关闭。部分原因是人们需要知道他们何时被录制。（[关于 Facebook][2]）

配备摄像头的智能眼镜在公共场合已经引发了重大的隐私担忧。（[《卫报》][4]）

因此，我会构建这样的架构：

```text
             摄像头
                │
                ▼
           本地推理
                │
                ▼
        结构化事件数据
                │
                ▼
        删除原始图像
                │
                ▼
           手机/云端
```

**默认原则：不存储世界。只存储用户的视觉统计数据。**

这是一种更好的产品理念。

# 我实际会做的原型

不要先制造眼镜。

使用：

**现有带摄像头的眼镜 → 手机 → 本地 VLM → SQLite 数据库 → 仪表板**

类似这样：

```bash
visionlab ingest
visionlab classify
visionlab timeline
visionlab stats
visionlab report
```

然后制作第一个仪表板：

```text
视觉实验室
────────────────────────────────

今天

📱 手机             1 小时 47 分
💻 电脑             5 小时 13 分
📖 阅读             42 分钟
🚗 驾车             51 分钟
🌳 户外             1 小时 32 分
👀 其他             2 小时 08 分

────────────────────────────────

平均观看距离

手机                37 厘米
电脑                61 厘米
阅读                43 厘米

────────────────────────────────

7 天趋势

近距离用眼            +18%
户外活动              -11%
手机使用               +7%

────────────────────────────────

[ 询问 Vision AI ]
```

**然后**，一旦软件证明了其价值，再针对你实际需要的传感器，去定制硬件。

美妙之处在于：**第一个原型主要依靠软件**。硬件初期只需一副带摄像头的眼镜。

这并非科幻：Meta 的 Project Aria Gen 2 已经作为一个眼镜平台存在，它配备了多种传感器、板载机器感知和音频，专为从事机器感知和 AI 应用的研究人员打造。（[Meta AI][5]）

我的押注是：

> **先不要造“数字眼镜”，先造一个“视觉活动记录器”。**

然后，眼镜才会成为传感器平台。

这样，路线图就变成了：

```text
V0   手机 + 现有眼镜
 ↓
V1   视觉活动记录器
 ↓
V2   眼动追踪
 ↓
V3   个人视觉模型
 ↓
V4   自适应眼镜
 ↓
V5   视觉操作系统
```

这是一个 **非常 AI 原生的硬件/软件创业方向**。
