是的。这实际上是一个非常重要的学习模式。

一篇随机的文章是**被动信息**：

```
阅读 → 理解一部分 → 遗忘
```

你的大脑没有牢固的“挂钩”来附着知识。

但当你有一个具体的疑问时：

```
我想理解为什么 GPU tile matmul 更快
        ↓
阅读 CUDA kernel 文章
        ↓
寻找“tiling 发生在哪里？”
        ↓
在脑海中模拟矩阵乘法
        ↓
知识连接到已有模型
```

现在这篇文章变成了**解决问题的工具**，而不是需要消费的内容。

这与研究人员和工程师的学习方式非常接近：

1. **遇到问题**
2. **构建一个粗略的心智模型**
3. **找到缺失的部分**
4. **阅读论文/文档/源码**
5. **动手实现**
6. **更新心智模型**

例如，你最近学习 vLLM/nano-vLLM 的过程：

一开始：

> “vLLM 使用 KV cache”

只是一句话。

但当你问：

> “为什么 decode 阶段会成为内存带宽瓶颈？”
>
> “为什么 prefill 像矩阵乘法，而 decode 像向量运算？”
>
> “为什么 PagedAttention 需要 block？”

这时阅读 vLLM 论文就变得容易多了，因为每一段都在回答你已经有的问题。

CUDA 也是如此：

没有疑问时：

> “GPU 有 SM、warp、shared memory、tensor core……”

很容易失去注意力。

有了疑问时：

> “为什么 2048×2048 的矩阵乘法比 2047×2047 运行得更好？”

你会自然深入探究：

```
矩阵
  ↓
tile
  ↓
block 调度
  ↓
warp
  ↓
shared memory 复用
  ↓
tensor core 形状
  ↓
内存对齐
```

疑问创造了一条路径。

一个优秀工程师的学习循环通常是：

```
构建 → 遇到限制 → 问为什么 → 阅读 → 修改 → 测量
```

而不是：

```
读 100 篇教程 → 希望某天有用
```

这也是为什么自己搭建小型系统（nanoGPT、nano-vLLM、CUDA kernel）如此强大。一个 bug 或性能问题会产生非常具体的问题，而这些疑问能让艰深的论文更容易吸收。

你现在会问像“tile 乘法到底如何计算 A[i,j]？”这样的问题，这是一个比读完许多文章更好的学习信号。你正在从**消费者模式**转向**探究者模式**。
