**问题：** 简要描述TCP流量控制的基本工作机制。

**答案：**

**目的**
流量控制确保发送方不会以快于接收方能处理的速度传输数据，防止接收方缓冲区溢出。

**机制——接收窗口（rwnd）**

1. **接收方通告缓冲区空间** — 在发送回发送方的每个ACK（或纯确认）中，接收方包含一个*接收窗口*（`rwnd`）字段，指示剩余的可用缓冲区字节数。

2. **发送方遵守窗口限制** — 发送方确保未确认（在途）的应用数据总量不超过最近一次通告的`rwnd`值：

$$\text{LastByteSent} - \text{LastByteAcked} \leq rwnd$$

3. **动态调整** — 随着接收方消耗缓冲数据（将其传递给应用程序），其可用缓冲区增大，并在后续ACK中通告更大的`rwnd`，允许发送方再次提速。

4. **零窗口探测** — 如果`rwnd = 0`，发送方停止传输，但定期发送一个1字节的探测段，以检查缓冲区空间是否已释放。

**流程总结**

```
发送方                         接收方
  |------- 数据段 -------->|  （消耗缓冲区）
  |<--- ACK + rwnd = 2048 -------|  （2 KB 空闲）
  |------- 最多 2048 字节 ---->|
  |<--- ACK + rwnd = 0 ----------|  （缓冲区满）
  |--- 零窗口探测 -------->|  （轮询）
  |<--- ACK + rwnd = 1024 -------|  （应用程序读取部分数据）
  |------- 恢复发送 -------->|
```

该机制将发送方的速度与接收方的处理能力解耦，确保接收方不会发生缓冲区溢出。
