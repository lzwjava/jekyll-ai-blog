问题：**为什么 SNMP 使用 UDP 而不是 TCP？**

回答：核心原因是 **SNMP 专为监控/控制而设计，在这种情况下，简单性、低开销和鲁棒性比可靠的字节流传输更为重要。**

### 1. SNMP 消息是独立的

一次 SNMP 请求的基本形式如下：

```text
管理器                   代理
   |                         |
   | ---- UDP 请求 ------> |
   | <---- UDP 响应 ------ |
```

每条 SNMP 消息都是一个完整的应用层消息。

SNMP 不需要像 HTTP/TCP 那样的连续流：

```text
TCP:
[连接] [字节流................] [关闭]
```

相反：

```text
SNMP:
请求 #1  ---> 响应 #1
请求 #2  ---> 响应 #2
请求 #3  ---> 响应 #3
```

UDP 天然适合这种**面向数据报**的模型。

### 2. 监控在网络异常时也必须正常工作

设想一个网络管理系统监控 10000 台路由器。

如果 SNMP 使用 TCP，每台设备可能都需要一个 TCP 连接：

```text
管理器
 ├── TCP ── 路由器 A
 ├── TCP ── 路由器 B
 ├── TCP ── 路由器 C
 ...
 └── TCP ── 路由器 10000
```

这是不必要的状态开销。

使用 UDP：

```text
管理器
 ──UDP──> 路由器 A
 ──UDP──> 路由器 B
 ──UDP──> 路由器 C
 ...
```

无需连接建立或持久连接状态。

当你监控的对象**正是网络本身**时，这一点尤其有用。

### 3. SNMP 实现自己的超时/重试机制

UDP 不保证交付。

SNMP 在应用层处理这个问题：

```text
发送请求
     |
     v
等待 N 秒
     |
     +---- 收到响应 ---> 成功
     |
     +---- 超时 ----> 重试
                       |
                       +--> 再次超时
```

例如，概念上如下：

```python
for attempt in range(3):
    send_udp(请求)

    response = recv(timeout=2)

    if response:
        return response

raise TimeoutError()
```

SNMP 不需要 TCP 的：

* 连接建立
* 序列号
* 重传机制
* 拥塞控制机制
* 有序字节流

因为一次 SNMP 操作本身就是一个**离散的请求/响应事务**。

### 4. UDP 开销小得多

TCP 需要维护连接状态：

```text
TCP:
SYN
SYN-ACK
ACK
数据
...
FIN
```

SNMP 可以简单地：

```text
UDP:
请求
```

这对于小型管理消息非常有价值。

一次典型的 SNMP 请求可能只是询问：

```text
"你的 CPU 利用率是多少？"
```

或者：

```text
"接口 GigabitEthernet0/1 的字节计数器是多少？"
"

对于这样微小的事务，建立可靠流的价值不大。

### 5. SNMP 仍能检测到许多故障

SNMP 的模型是：

```text
UDP
 ↓
SNMP 请求
 ↓
超时/重试
 ↓
应用判定设备不可达
```

这对于网络管理实际上有一个重要特性。

如果路由器停止响应：

```text
SNMP 超时
      ↓
设备可能宕机
      ↓
生成告警
```

当网络出现故障时，你通常不希望 TCP 继续尝试维持连接。

### 为什么不用 TCP？

设计权衡大致如下：

| 属性                     |                       UDP |          TCP |
| ------------------------ | ------------------------: | -----------: |
| 需要连接                 |                        否 |          是 |
| 可靠交付                 |                        否 |          是 |
| 有序流                   |                        否 |          是 |
| 重传                     | 应用层可实现             |     内置 |
| 开销                     |                       低 |       更高 |
| 适合独立查询             |                   **是** | 不太自然 |
| 适合连续流               |                        否 |      **是** |

因此基本设计是：

> **SNMP 不需要可靠流，它需要轻量级的请求/响应数据报。**

一个有趣的例外：**SNMPv3 在某些部署中可以使用 TCP**，并且较新的 SNMP 传输映射可以支持其他传输方式。但经典的 SNMP 绝大多数情况下使用 **UDP 端口 161** 进行请求，使用 **UDP 端口 162** 发送陷阱/通知。
