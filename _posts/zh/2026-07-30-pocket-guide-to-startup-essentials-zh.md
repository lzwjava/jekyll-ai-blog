## 问题：什么是 Y Combinator 的《初创公司口袋指南》？

## 答案：

**YC 口袋指南**是 Y Combinator 核心创业理念的浓缩版本。它本质上就是 YC 传授的创始人操作系统：**快速发布、与用户交流、找到产品-市场契合点、保持小团队、激进迭代**。YC 曾发布过类似列表，名为“YC 的必备创业建议”。（[Y Combinator][1]）

整个理念可以概括为：

> **初创公司并非规模更小的公司。它是一台寻找可复现价值创造方式的机器。**

### 1. 立即发布

不要花 6 个月打造完美产品。

错误做法：

```
想法
  ↓
架构
  ↓
设计文档
  ↓
招聘
  ↓
发布
```

YC 风格：

```
想法
  ↓
构建简陋 MVP
  ↓
用户
  ↓
反馈
  ↓
迭代
  ↓
产品-市场契合
```

市场会给你需求规格。

---

### 2. 打造人们想要的东西

这是 YC 版本的“北极星”。

不是：

> “我们能造出这个吗？”

而是：

> “如果这个东西消失了，会有人感到难过吗？”

例子：

* Dropbox：

  * 不是“云存储技术”
  * 问题：“我需要随处访问我的文件”

* Airbnb：

  * 不是“市场网站”
  * 问题：“酒店太贵，人们有闲置房间”

---

### 3. 做不能规模化的事

早期创始人应该手动解决问题。

例子：

Airbnb 早期：

```
创始人 → 拜访公寓
创始人 → 拍照
创始人 → 与房东交谈
创始人 → 获取房源
```

不是：

```
先构建自动化市场系统
```

手工劳动能让你了解真正的问题。

---

### 4. 找到 10-100 个热爱你产品的客户

YC 不关心虚荣指标。

错误做法：

```
100,000 注册用户
```

正确做法：

```
50 个用户
  |
  +-- 每天使用
  +-- 服务中断时抱怨
  +-- 付费
  +-- 推荐朋友
```

前 100 个客户就是你的产品设计团队。

---

### 5. 写代码，与用户交流

很多技术型创始人躲在工程后面。

例子：

```
第1个月：
  重写后端
  优化数据库
  搭建 Kubernetes 集群

用户：
  零
```

YC 创始人：

```
上午：
  与5个用户交流

下午：
  实现用户要求的功能
```

---

### 6. 找到 90/10 解决方案

不要优化所有东西。

找到能创造最大价值的最小事物。

例子：

你想要一个 AI 编程助手。

错误做法：

```
构建：
- 自有模型
- 自有 IDE
- 自有云
- 自有向量数据库
- 自有代理框架
```

正确做法：

```
第1天：
OpenAI API
+
VSCode 扩展
+
一个杀手级工作流程
```

然后再扩展。

---

### 7. 增长来自产品，而非营销

YC 的观点：

```
优秀产品
      |
      ↓
用户告诉他人
      |
      ↓
增长
```

不是：

```
糟糕产品
      |
      ↓
Facebook 广告
      |
      ↓
增长
```

营销可以放大好东西，但很少能修复坏东西。

---

### 8. 在找到产品-市场契合前保持小团队

在 PMF 之前：

```
2 位创始人
100 个用户
快速迭代
```

PMF 之后：

```
工程团队
销售
营销
运营
```

过早招聘会滋生官僚主义。

---

### 9. 忽略竞争对手

YC 著名的思维模式：

你最大的敌人通常不是另一家公司。

而是：

* 构建无人想要的东西
* 行动太慢
* 学习速度耗尽

竞争只有在需求被证实后才重要。

---

### 10. 创始人关系至关重要

YC 强烈强调联合创始人关系。

因为初创公司意味着：

```
不确定性
+
压力
+
失败
+
长期无回报
```

糟糕的联合创始人关系比技术问题更快摧毁公司。

---

## 针对 2026 年的 AI 初创公司，YC 版本变为：

### 第1周

构建：

```
AI 代理
+
一个痛苦的工作流程
+
10 个目标用户
```

例子：

```
中国制造商的 AI 助手

不要：
"AI 平台"

要做：
"自动生成出口文档"
```

---

### 第1个月

目标：

```
10 个用户热爱它
```

不是：

```
10,000 注册用户
```

---

### 第3个月

目标：

```
人们付费
```

例子：

```
$50/月 × 100 个客户
=
$5k MRR
```

现在你有了证据。

---

YC 的完整哲学：

```
构建 → 发布 → 交流 → 学习 → 迭代

重复100次
```

创始人本质上是在进行科学实验。

YC 初创公司图书馆收集了这些原则及相关创始人资源。（[Y Combinator][2]）

对于构建 AI 代理/咨询产品的人来说，最相关的 YC 规则可能是：

> **不要构建 AI 平台。找到一个昂贵的人工工作流程并用它替换掉。**

这就是许多 YC AI 公司应对当前浪潮的方式。
