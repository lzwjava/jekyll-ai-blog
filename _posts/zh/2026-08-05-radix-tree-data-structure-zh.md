**radix tree**（也称为 **compressed trie**、**compact prefix tree**，或常见变体中的 **Patricia trie**）是一种树形数据结构，用于存储字符串或其他序列，其中**公共前缀被共享**，并且单子节点的链被压缩为单条边。

### 从普通 trie 开始

假设你存储以下单词：

```
cat
car
cart
dog
```

一个普通的 trie 看起来像这样：

```
(root)
 ├── c
 │    └── a
 │         ├── t
 │         └── r
 │              └── t
 └── d
      └── o
           └── g
```

每条边代表一个字符。

---

### radix tree 压缩路径

注意有些路径没有分支：

* `c → a`
* `d → o → g`

这些路径可以被压缩为更长的边标签：

```
(root)
 ├── "ca"
 │      ├── "t"
 │      └── "r"
 │            └── "t"
 └── "dog"
```

每条边存储的不再是单个字符，而是一个**字符串**。

这显著减少了节点的数量。

---

## 查找是如何工作的

假设你搜索 `"cart"`。

1. 从根节点开始。
2. 匹配 `"ca"`。
3. 剩余字符串为 `"rt"`。
4. 沿着边 `"r"` 前进。
5. 剩余字符串为 `"t"`。
6. 沿着边 `"t"` 前进。
7. 找到单词。

与 trie 不同，你在每条边上**一次比较多个字符**。

---

## 插入示例

假设树中只包含：

```
"dog"
```

```
(root)
 └── "dog"
```

现在插入：

```
dot
```

最长公共前缀是 `"do"`。

拆分边：

```
(root)
 └── "do"
      ├── "g"
      └── "t"
```

边拆分是 radix tree 中的关键操作。

---

## 为什么使用 radix tree？

### 节省内存

普通 trie 有很多只有一个子节点的节点。

例如：

```
international
```

trie 会为每个字符创建一个节点。

而 radix tree 将：

```
"international"
```

存储为单条边（如果没有分支的话）。

---

### 快速前缀搜索

查找所有以：

```
inter
```

开头的单词非常高效，因为公共前缀只存储一次。

应用场景包括：

* 自动补全（autocomplete）
* 拼写检查（spell checking）
* 路由表（routing tables）
* IP 前缀匹配（IP prefix matching）
* 字典（dictionaries）
* 搜索引擎（search engines）

---

## 时间复杂度

设：

* **n** = 搜索字符串的长度

| 操作 | 复杂度 |
| ------------ | -------------------------- |
| 查找 (Search) | O(n) |
| 插入 (Insert) | O(n) |
| 删除 (Delete) | O(n) |
| 前缀搜索 (Prefix search) | O(前缀长度 + 结果数量) |

虽然边标签可能包含多个字符，但检查的字符总数与键的长度成正比。

---

## 与 trie 的比较

| Trie                       | Radix Tree                         |
| -------------------------- | ---------------------------------- |
| 每条边一个字符             | 每条边多个字符                     |
| 节点多                     | 节点更少                           |
| 内存占用更多               | 内存占用更少                       |
| 实现更简单                 | 因边拆分而更复杂                   |
| O(n) 查找                  | O(n) 查找                          |

## 小示例

存储：

```
bear
bell
bid
bull
buy
sell
stock
stop
```

trie 会为每个字符创建一个节点。

radix tree 可能看起来像这样：

```
(root)
├── "b"
│    ├── "e"
│    │    ├── "ar"
│    │    └── "ll"
│    ├── "id"
│    └── "u"
│         ├── "ll"
│         └── "y"
└── "s"
     ├── "ell"
     └── "to"
          ├── "ck"
          └── "p"
```

公共前缀被共享，而长且无分支的路径被压缩。

---

## 直觉理解

你可以这样理解这个演进过程：

* **二叉搜索树（Binary Search Tree）：** 通过排序来组织数据。
* **Trie：** 通过**逐字符**来组织数据。
* **Radix Tree：** 通过**共享公共前缀**来组织数据，但将长且无分支的路径压缩为单条边以节省空间。

radix tree 的主要优势在于，它保留了 trie 快速前缀搜索的能力，同时对于许多键共享长前缀的数据集，使用更少的内存。
