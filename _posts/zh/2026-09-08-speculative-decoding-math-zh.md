问题：**投机解码背后的数学原理是什么？**

答案：

设：

* \\(p(x)\\) = **大型目标模型**的概率分布
* \\(q(x)\\) = **小型草稿模型**的概率分布

问题在于我们希望从 \\(p\\) 中采样，但评估 \\(p\\) 的计算成本很高。

### 1. 草稿模型生成候选 token

假设草稿模型生成了 \\(K=5\\) 个 token：

```text
上下文
   ↓
草稿 q
   ↓
t1 → t2 → t3 → t4 → t5
```

例如：

```text
"法国的首都是"
        ↓
"巴黎是世界上最"
```

草稿模型以自回归方式生成了这些 token，因此它计算：

$$
q(t_1|x)
$$

然后

$$
q(t_2|x,t_1)
$$

依此类推。

### 2. 目标模型并行评估所有 token

现在来看关键技巧。

我们不再让大模型依次执行：

```text
x → t1
x,t1 → t2
x,t1,t2 → t3
x,t1,t2,t3 → t4
x,t1,t2,t3,t4 → t5
```

而是构造一个序列：

```text
x t1 t2 t3 t4 t5
```

然后运行 **一次 Transformer 前向传播**。

由于 Transformer 的训练/推理在已知序列上是天然可并行化的（按位置），目标模型可以在同一次前向传播中计算出：

$$
p(t_1|x)
$$

$$
p(t_2|x,t_1)
$$

$$
p(t_3|x,t_1,t_2)
$$

$$
...
$$

这就是核心的性能优化技巧。

## 3. 但我们可以直接接受草稿 token 吗？

不行。

假设对于一个 token：

```text
草稿 q:
A = 0.8
B = 0.2

目标 p:
A = 0.4
B = 0.6
```

草稿强烈偏好 A，但目标偏好 B。

如果我们盲目接受草稿，就会改变目标模型的分布。

相反，投机解码采用了一种巧妙的 **接受/拒绝采样规则**。

对于提议的 token \\(x\\)：

$$
a(x)=\min\left(1,\frac{p(x)}{q(x)}\right)
$$

因此草稿 token 被接受的概率为：

$$
\boxed{\min(1,p(x)/q(x))}
$$

### 示例

草稿：

$$
q(A)=0.8
$$

目标：

$$
p(A)=0.4
$$

则：

$$
a(A)=\frac{0.4}{0.8}=0.5
$$

所以 A 有 **50% 的概率被接受**。

---

### 另一个示例

草稿：

$$
q(B)=0.2
$$

目标：

$$
p(B)=0.6
$$

则：

$$
a(B)=\min(1,0.6/0.2)=1
$$

所以 B **总是被接受**。

这很直观：

> 如果目标模型对某个 token 的偏好程度不低于草稿模型，就没有理由拒绝它。

# 4. 当 token 被拒绝时会发生什么？

这是最精妙的部分。

假设草稿提议了：

```text
t1 t2 t3 t4 t5
```

并且：

```text
t1 ✓
t2 ✓
t3 ✓
t4 ✗
```

我们保留：

```text
t1 t2 t3
```

然后，我们并不是丢弃所有内容，而是从一个 **残差分布** 中采样替换 token：

$$
r(x)
=
\frac{\max(0,p(x)-q(x))}
{\sum_y\max(0,p(y)-q(y))}
$$

即：

$$
\boxed{
r(x)=
\frac{[p(x)-q(x)]_+}
{\sum_y[p(y)-q(y)]_+}
}
$$

其中

$$
[z]_+=\max(0,z)
$$

这个修正分布包含了目标模型比草稿模型 **多出的** 概率质量。

---

# 5. 为什么这能保持目标分布不变？

这是其优美的数学性质。

对于 token \\(x\\)，有两种方式可以成为输出：

### 接受草稿

草稿以概率 \\(q(x)\\) 选择 \\(x\\)，我们以以下概率接受它：

$$
\min(1,p(x)/q(x))
$$

因此：

$$
q(x)\min(1,p(x)/q(x))
=
\min(q(x),p(x))
$$

所以被接受的概率质量为：

$$
\min(p(x),q(x))
$$

### 拒绝修正

剩余的概率质量为：

$$
p(x)-\min(p(x),q(x))
$$

正好是：

$$
[p(x)-q(x)]_+
$$

经过归一化后，残差分布恰好给出了这部分缺失的质量。

因此：

$$
\underbrace{\min(p(x),q(x))}_{接受部分}
+
\underbrace{[p(x)-q(x)]_+}_{修正部分}
=
p(x)
$$

完美。

所以最终样本的分布 **严格等于 \\(p\\)**。

这就是投机解码不仅仅是一种近似方法的原因。

# 6. 实际应用图景

将目标模型视为：

```text
        大型模型
       ┌─────────────┐
       │  70B / 400B │
       └──────┬──────┘
              │
        昂贵的单次前向传播
              │
              ▼
         1+ 个 token
```

投机解码增加了：

```text
             小型模型
             1B / 7B
                 │
         廉价生成
                 │
          t1 t2 t3 t4 t5
                 │
                 ▼
        ┌─────────────────┐
        │   大型模型       │
        │   一次验证所有   │
        └─────────────────┘
                 │
          ✓ ✓ ✓ ✓ ✗
                 │
                 ▼
           输出 4 个 token
```

如果草稿模型非常好，你可能会得到类似这样的结果：

```text
草稿:    t1 t2 t3 t4 t5 t6
目标:   ✓  ✓  ✓  ✓  ✓  ✗
                         ↑
                    修正
```

这样，不再需要 **6 次独立且昂贵的目标模型迭代**，你只进行了大约 **一次目标模型验证迭代**。

# 7. 为什么这对 LLM 推理特别有效

仅解码器 Transformer 有两种截然不同的计算模式。

**自回归生成：**

```text
token 1 → 前向传播
token 2 → 前向传播
token 3 → 前向传播
token 4 → 前向传播
```

依赖关系是顺序的。

但当 token 已经被提议出来时：

```text
token 1
token 2
token 3
token 4
   ↓
一次 Transformer 前向传播
```

Transformer 可以同时处理这些位置。

因此，投机解码将部分 **顺序解码问题转化为并行验证**。

GPU 更乐意执行：

$$
\text{对多个位置进行大型矩阵运算}
$$

而不是反复启动昂贵的目标前向传播来生成一个新 token。

## 8. 与 KV 缓存的关系

这也与你之前问的 KV 缓存问题直接相关。

在正常生成过程中：

```text
KV 缓存: [旧 token]
              +
新 token
              ↓
         目标前向传播
              ↓
         添加新的 K,V
```

使用投机解码：

```text
KV 缓存: [旧 token]

草稿模型:
    生成 t1 t2 t3 t4 t5

目标:
    KV 缓存 + [t1 t2 t3 t4 t5]
                    ↓
             一次验证
                    ↓
              ✓ ✓ ✓ ✓ ✗
```

目标模型可以计算提议序列的 K/V，并在一次前向传播中评估所有这些 next-token 分布。

这就是为什么在高性能推理引擎中，投机解码和 KV 缓存紧密相关。
