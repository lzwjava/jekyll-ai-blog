这是 **GRPO 实验的第 1 次运行** — 保存于 `./grpo_qwen15b_math/final`（检查点 750/760，`epoch: 2`，760 步）。我提取了完整的 `trainer_state.json` 来解读。以下是这些数字的实际含义。

## 实验内容

采用的是强化学习而非监督微调：使用**基础** Qwen2.5-1.5B（无 SFT，无指令微调），每个算术提示生成 4 个补全，并给予以下奖励：

- `reward_format` — 格式正确的 `thinking… response` 块，最高 +0.3
- `reward_correctness` — 正确 +1.0 / 错误 −0.5 / 无回答 −0.7

目标是让链式思维算术在基础模型中涌现。配置：760 步，约 1 小时 45 分钟（8.3 秒/步），40 个评估提示，31 次评估。

## 解读关键数字

| 指标 | 数值 | 含义 |
| --- | --- | --- |
| `train_loss` | −0.0090 | **不是交叉熵损失。** 它是 GRPO 策略梯度替代值；接近零表示优势≈零，即*无信号*，而非"良好收敛"。 |
| `eval_reward` | 0.9238 | 评估组的平均奖励。但由于格式奖励为 0，这*纯*是正确率。 |
| `eval_rewards/reward_format/mean` | **0.0（标准差 0.0）** | 🚩 你试图教的行为**从未发生** — 在 760 个训练步和每次评估中都是如此。 |
| `eval_frac_reward_zero_std` | **0.85** | 🚩 85% 的提示组中，4 个生成的奖励*相同* → 优势为零 → 无梯度。只有 15% 的组提供了学习信号。 |
| `eval_kl` | 0.030 | 策略相对于参考模型几乎未移动。beta=0.02 + 死掉的优势 ≈ 模型冻结。 |

最终生成证实了这一点：`(7 + 5) * 3 = 36` 和 `1834 + 596 = 2430` 都正确且带逐步说明 — 但**没有 `thinking` 标签**，因为从未教过该协议。

（另外：`eval_num_tokens: 6.554e5` 是 31 次评估的累计值，而非单次 — ≈ 每次补全 token 数 × 补全数 × 评估次数。`eval_samples_per_second 0.64 × 62.5 秒 = 40` 确认了评估集大小。）

## 实验的实际含义

**这是一个科学上干净的负面结果 — 流水线正常，但能力未提升。**

1. **任务没有余量。** 标准合成数据集中，未动的基础模型已解决了约 83%。因此每组 4 个样本中，奖励通常相同 → `zero_std` 升至 0.85 → GRPO 无信号可学。这是典型的"奖励饱和"失败。注意评估中 `reward` 从 0.64 升至 0.92，但因 85% 死组，该上升主要是模型稳定在既有模式，而非学习。

2. **格式奖励不可达。** 基础模型对精确的 `thinking… response` token 对分配的概率几乎为零，因此格式项在每组中恒为 0 → 零优势 → 无法获取该行为。你无法从 ±1.0 的正确性信号中引导出精确 token 协议。

3. **表面上的"提升"大多是假象。** 根据你自己的 `run2.sh` 分析：在 run 1 有 bug 的答案提取下，基础模型得分为约 82.8%，而移至 92.4% 的大部分是策略学会**停止输出多余的尾部 `response`** — 一种 token 习惯，而非算术技能。修复提取后显示，该分布上基础模型贪心解码已约 100%。

4. **它真正学到的是：** 回答更短（长度下降，熵崩溃）、无推理回答、并丢弃多余标签。仅此而已。

## 结论

`奖励 ↑` ≠ `能力 ↑`。此运行展示了 GRPO 所需的结构性前提，两者都缺失：

- **混合结果组（余量）** — 在 `run2.sh` 中通过 `--difficulty harder`（3 位数加减、2 位数乘法）修复。
- **可达的目标行为** — 通过 `--format-warmup 512` 修复，在 RL 开始前将标签协议监督训练至约 0.30 格式奖励。

使用 `headroom.py` 在训练前验证类别处于约 **20–70%** 的基础准确率区间。并忽略接近零的 `eval_loss` 作为质量信号 — 当 `frac_reward_zero_std = 0.85` 时，它只是毫无动静的声音。
