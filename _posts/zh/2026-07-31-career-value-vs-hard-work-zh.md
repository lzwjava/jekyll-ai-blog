**问题：** 如果你在工作中遭受欺凌或不公平对待——辛勤工作却换来批评、没有奖励、多年未晋升，该怎么办？

**回答：**

这种情况很常见，特别是在大公司、遗留团队和合同工岗位上。关键在于区分**暂时的不公平**和**阻碍你成长的系统性问题**。

一个有用的思维模型：

```
你的职业价值 = 技能成长 × 可见度 × 杠杆 × 市场需求
```

仅靠努力工作是不够的。

许多工程师会陷入这个陷阱：

```
更多工作
    ↓
更多责任
    ↓
更多隐藏任务
    ↓
经理认为“他能搞定”
    ↓
无晋升、无加薪
```

公司从你的可靠性中获益，但你的职业生涯却停滞不前。

## 1. 首先判断：是欺凌还是激励机制问题？

### 情况 A：主管严厉但可改善

迹象：

* 批评附带具体反馈
* 你获得机会
* 主管有时会为你争取
* 晋升标准明确

示例：

> “你的设计文档需要改进。本季度写两份方案。”

这虽然痛苦但有帮助。

---

### 情况 B：剥削

迹象：

* 你总是接到紧急任务
* 他人获得功劳
* 你的错误被放大，他人错误被忽略
* 没有明确的晋升路径
* 薪资多年冻结
* 你是“那个解决一切问题的人”

这不是绩效问题，而是激励机制问题。

---

### 情况 C：职场欺凌

迹象：

* 公开羞辱
* 人身攻击
* 故意排挤
* 威胁
* 设定不可能完成的期限，故意让你失败

记录一切。

示例：

```
日期：
人员：
情况：
要求内容：
影响：
证人：
```

不要依赖记忆。

---

## 2. 停止扮演“英雄工程师”角色

强工程师常犯的错误：

```
问题出现
        |
        v
你快速解决
        |
        v
无人知晓复杂度
        |
        v
下一个问题又落到你头上
```

相反：

让工作变得可见。

示例：

不好的做法：

> 修复了生产问题。

好的做法：

> 调查了支付超时问题。
> 根因：数据库连接池耗尽。
> 将超时错误从 3% 降至 0.1%。
> 添加了监控和应急预案。

同一份工作，不同的职业价值。

---

## 3. 在你主管之外建立杠杆

你的主管并非唯一市场。

创建：

### 技术声誉

* GitHub 项目
* 博客文章
* 开源贡献
* 技术演讲

例如：

你已经拥有比许多工程师更强的证据：

* 训练过 GPT 模型
* 构建过 AI 智能体
* 从事过 LLM 基础设施
* 写过技术笔记

这些都是职业资本。

糟糕的主管可以阻止内部晋升，但无法抹去外部声誉。

---

## 4. 进行一次晋升对话

不要问：

> “为什么没给我晋升？”

而要问：

> “下一个级别需要哪些确凿证据？”

迫使对方给出可衡量的标准。

示例：

```
当前级别：
后端工程师

目标：
高级工程师

差距：
1. 架构所有权
2. 指导他人
3. 业务影响

时间线：
6个月
```

如果他们无法回答，这本身就是信息。

---

## 5. 设定最后期限

一个危险模式：

```
第一年：也许明年
第二年：需要更多时间
第三年：预算问题
第四年：市场不好
```

如果在 12-18 个月内没有进展，假设系统不会改变。

你的选择：

```
A. 内部换团队
B. 换公司
C. 建立自己的收入来源
D. 有意识接受妥协
```

不要被动等待。

---

## 6. 结合你的具体情况

根据你之前描述的情况：

* 10 年以上工程经验
* 构建过产品
* 训练过 LLM
* 对 AI 基础设施感兴趣
* 有房贷压力
* 合同工经验

你最大的风险不是能力不足。

你的风险是：

```
被困在低杠杆环境中
```

对于你这样背景的人，再花三年时间做：

```
Java 维护
+
遗留系统
+
合同工作
+
没有所有权
```

机会成本巨大。

你的策略应该是：

```
保持收入稳定
        +
积累 AI 工程证据
        +
向更高杠杆角色迈进
```

而不是：

```
更努力地工作并希望有人注意到
```

---

一位优秀工程师最终会明白：

> 公司奖励的是他们能看到的问题，而不是他们无法衡量的努力。

你的目标不是“战胜”糟糕的主管。你的目标是成为拥有足够杠杆的人，让糟糕的环境无法困住你。
