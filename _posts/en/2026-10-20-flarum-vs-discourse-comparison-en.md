**Question:** What are the differences between Flarum and Discourse?

**Answer:**

Here's a side-by-side breakdown:

| | **Flarum** | **Discourse** |
|---|---|---|
| **License** | MIT (more permissive) | GPL-2.0 |
| **Tech Stack** | PHP + Mithril.js | Ruby on Rails + PostgreSQL + Redis |
| **Hosting** | Standard PHP hosting | Requires Docker (more complex) |
| **UI/Design** | Modern, clean, minimalist | Feature-rich, denser |
| **Ease of Setup** | Easier | More technical overhead |
| **Performance** | Lighter, faster on small servers | Better at scale with proper hardware |
| **Ecosystem** | Smaller plugin/extension library | Much larger, mature ecosystem |
| **Community/Team** | Small (few core devs, part-time) | Large team + commercial company behind it |
| **Maturity** | Newer, smaller community | ~13 years old, widely battle-tested |
| **Managed Hosting** | Self-host only | Official hosting plans available |

**Key takeaways:**

- Discourse is enterprise-ready with a heavier stack (Ruby on Rails, PostgreSQL, Redis, Docker), while Flarum is a lightweight PHP alternative that's easier to install and faster on smaller servers.
- Flarum uses the MIT license, which is more permissive than Discourse's GPL-2.0, offering greater flexibility for commercial use and integration.
- The biggest difference between the two isn't just the code or features, but how each project is run — Discourse has a large team and a sustainable commercial business, while Flarum has a small core team working part-time.
- Discourse has a significantly larger community and plugin ecosystem compared to Flarum.

**Bottom line:** Choose **Flarum** if you want something lightweight, easy to deploy, and elegant for smaller communities. Choose **Discourse** if you need enterprise-scale features, a larger ecosystem, and long-term commercial backing.
